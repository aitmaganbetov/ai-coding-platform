# CREATE: новый проект из описания

`ai-coding create` проводит идею через шаги FR-03:

1. **Требования.** Requirements Agent пишет ТЗ: цели, функциональные и нефункциональные требования, user stories с критериями приёмки, допущения и открытые вопросы.
2. **Согласование версии ТЗ.** Вы утверждаете конкретную версию (`v1-…`) или отвечаете на открытые вопросы — тогда получается следующая версия (`v2-…`). Без утверждения архитектура не начинается.
3. **ADR и архитектура.** Architect Agent выбирает стек, разбивает систему на модули без циклических зависимостей, пишет ADR, проектирует API и модель данных.
4. **Backlog.** Planner Agent составляет задачи с зависимостями, оценками, приоритетами и milestones; каждое требование покрыто хотя бы одной задачей.
5. **Каркас (bootstrap).** Bootstrap Agent создаёт каркас по шаблону:
   - структуру модулей и тесты структуры;
   - CI;
   - README;
   - `.ai-coding.yml`;
   - `docs/` (ТЗ, архитектура, ADR, backlog).

   Каркас коммитится в ветку `ai/bootstrap`; основная ветка не меняется.
6. **Проверка.** Каждый файл в коммите сверяется по хэшу с тем, что создал агент.
7. **PR** (с `--pr`). Ветка пушится, PR открывается (approval `pr_create`). Merge выполняете вы.

## Что нужно

- **LLM.** В конфигурации включите раздел `ai` (см. [configuration.md](configuration.md)).
  - Офлайн: Ollama или vLLM (`provider: ollama`), без ключей и без выхода в сеть.
  - Внешний провайдер (`openai`, `anthropic`): нужен ключ в переменной окружения, `security.network: allowlist` с хостом провайдера и, по умолчанию, approval `external_llm`.
- **git.**
- **Для `--pr`:**
  - `GITHUB_TOKEN` или GitHub App (см. [github.md](github.md));
  - remote `origin` в целевом репозитории.

## Пример

```bash
ai-coding create "Сервис коротких ссылок со статистикой переходов" --dest ./shortener --config ./platform.yml
```

В терминале ответьте на каждый запрос:

- **Требования:** `approve` — утвердить, `revise` — ответить на вопросы и получить новую версию, `stop` — выйти.
- **Критичные файлы** (`.github/**`, `.ai-coding.yml`, lock-файлы): `approve` или `stop`.
- **Внешняя модель** (если настроена): `approve` или `stop`.

## Без терминала (CI, скрипты)

Без TTY или с `--no-interactive` прогон останавливается на решении и печатает команды для продолжения:

```bash
ai-coding create --idea-file idea.md --dest ./shortener --config ./platform.yml --no-interactive
```

```bash
ai-coding run approve <RUN> -C ./shortener
```

```bash
ai-coding create --resume <RUN> --dest ./shortener
```

Чтобы ответить на открытые вопросы и получить новую версию ТЗ:

```bash
ai-coding create --revise <RUN> --answers answers.yml --dest ./shortener --no-interactive
```

`answers.yml` — соответствие «id вопроса → ответ», например `Q-01: Ссылки живут 30 дней`.

## Опции

| Опция | Назначение |
| --- | --- |
| `IDEA` / `--idea-file F` | Описание проекта |
| `--dest DIR` | Каталог проекта: новый, пустой или git-репозиторий |
| `--config F` | Конфигурация платформы (раздел `ai`, политика, бюджеты). Сохраняется в `DIR/.ai-coding/config.yml`, поэтому для `--resume` и `--revise` её можно не указывать |
| `--name`, `--constraint` (повторяемая) | Имя проекта, жёсткие ограничения |
| `--branch` (по умолчанию `ai/bootstrap`), `--base` (по умолчанию `main`) | Рабочая и базовая ветки. Существующая рабочая ветка не перезаписывается |
| `--resume RUN`, `--revise RUN --answers F` | Продолжить прогон; новая версия ТЗ |
| `--pr`, `--repo owner/name`, `--pr-title` | Push и PR после проверки каркаса |
| `--interactive/--no-interactive` | По умолчанию — интерактивно, если stdin является терминалом |
| `--dry-run`, `--require-approval` | Показать план, ничего не создавать; требовать approval на каждую защищённую операцию |

## Гарантии

- **Только данные, не инструкции.** Входы агентов (идея, предыдущая версия, ответы) передаются модели как данные в разделителях `<input>`; инструкции из них не исполняются.
- **Проверка ответов.**
  - Ответ модели проверяется по JSON Schema агента (`ai_coding/schemas/agents/`).
  - Затем семантически: уникальные id, существующие ссылки, отсутствие циклов, покрытие требований.
  - Ошибочный ответ модель исправляет не более двух раз; если исправить не удалось, шаг проваливается.
- **Секреты.** Маскируются до отправки в модель, в кэше ответов, в логах и в артефактах.
- **Учёт и бюджеты.**
  - Расход токенов и стоимость каждого вызова записываются в `model_usage`.
  - Бюджет проверяется до отправки запроса.
  - При исчерпании бюджета прогон ставится на паузу.
- **Повторы без дублей.** Повтор шага или `--resume` не создаёт второй коммит или PR: работают журнал эффектов и trailer `AI-Coding-Run`.
- **Без merge.** Платформа никогда не делает merge и не меняет основную ветку.

## Поддерживаемые стеки каркаса

| Язык в архитектуре | Каркас |
| --- | --- |
| python | uv, pytest, ruff; CI на `astral-sh/setup-uv` |
| javascript, typescript | Node.js ≥ 20, `node --test`; CI на `actions/setup-node` |

Если архитектор выбрал другой язык, шаг bootstrap завершится сообщением «не поддерживается». В этом случае укажите стек ограничением, например `--constraint "Python 3.12"`.
