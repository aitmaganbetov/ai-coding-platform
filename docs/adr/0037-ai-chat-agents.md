# ADR-0037: Чат с ИИ в рабочей области (Claude Code и Codex в фоне, как в VS Code)

- Статус: Принято
- Дата: 2026-11-06
- Уточняет: [ADR-0036](0036-workspaces-and-browser-terminal.md)

## Контекст

Пользователям нужен не терминал, а чат с ИИ, как в расширениях Claude Code for VS Code и Codex for VS Code. Официальные CLI должны работать в фоне и не останавливаться, когда закрыта вкладка.

Как устроены расширения (изучено 2026-11-06):

- **Claude Code for VS Code** содержит свою копию CLI и рисует чат поверх неё:
  - потоковые ответы и карточки инструментов;
  - diff правок с кнопками принять/отклонить;
  - запросы разрешений и режимы «Manual (ask) / Edit automatically / Plan / Auto»;
  - история сессий, выбор модели.

  Вход — подпиской Claude или аккаунтом Anthropic Console.
- **Codex for VS Code** работает поверх `codex app-server`: JSON-RPC по stdio, потоки и ходы, события `item/*`, запросы одобрения команд и правок, вход в ChatGPT (в том числе по device-коду).

Протоколы проверены на версиях, которые ставит наш образ:

- **Claude Code 2.1.309** запускается так: `claude -p --input-format stream-json --output-format stream-json --verbose --include-partial-messages --permission-prompts host --permission-prompt-tool stdio`.
  - Запрос разрешения приходит как `control_request` с подтипом `can_use_tool` (поля `tool_name`, `input`, `tool_use_id`, `permission_suggestions`).
  - Ответ — `control_response` с `behavior: allow | deny`.
  - Без `--permission-prompt-tool stdio` такие запросы автоматически отклоняются.
  - Результаты правок содержат `structuredPatch`.
- **Codex 0.163.0:** схема протокола выгружена командой `codex app-server generate-json-schema`.
  - Песочница Codex (bubblewrap) в контейнере без user namespaces не работает. Поэтому ход идёт с `sandboxPolicy: externalSandbox`: изоляцию даёт контейнер рабочей области.

## Решение

1. **Фоновая служба `ai-coding-agent`** (`deploy/workspace/ai-coding-agent`, только стандартная библиотека Python) работает в контейнере рабочей области пользователя.
   - Слушает Unix-сокет в `/tmp`.
   - Claude Code держит как процесс `claude -p` в режиме stream-json на каждый чат. Ходы идут в тот же процесс, после перезапуска — `--resume <session>`.
   - Codex держит одним процессом `codex app-server` на все чаты: потоки, `turn/start`, `turn/interrupt`.
   - События обоих агентов приводит к общему виду: `user`, `delta`, `message`, `thinking`, `tool`, `tool_result` (с diff), `approval`, `approval_done`, `turn`, `auth_required`, `notice`, `planned`.
   - Каждый чат пишет в `~/.ai-coding/chats/<project>/<id>.jsonl` (домашняя папка пользователя).
   - Новому подключению служба воспроизводит историю.
   - Ход, оборванный перезапуском, закрывается в истории как прерванный.
2. **Работа в фоне.** Агент не зависит от браузера: закрытая вкладка ничего не останавливает. Запрос разрешения ждёт, пока пользователь вернётся. Работающий агент или открытый чат считаются активностью: такой контейнер уборщик не удаляет и при обновлении образа не пересоздаёт.
3. **Транспорт.** `WS /api/v1/projects/{id}/workspace/chat`.
   - Аутентификация первым сообщением, права `workspace.use`.
   - Брокер подключается к службе через `docker exec -i … ai-coding-agent connect`. В docker-compose это делается через сервис рабочих областей по подписанному тикету.
   - Из браузера к службе проходят только операции чата: `hello`, `new`, `open`, `send`, `approve`, `interrupt`, `login`.
4. **Разрешения**, как в VS Code: кнопки «Разрешить», «Разрешить в этой сессии» (сессионные `permission_suggestions` Claude, `acceptForSession` у Codex) и «Отклонить» прямо в карточке действия.
   - Режимы: «Спрашивать», «Править файлы без вопросов», «Только план» (Claude), «Полный доступ».
   - Соответствие у Claude: `default`, `acceptEdits`, `plan`, `bypassPermissions`.
     Чтобы «Полный доступ» можно было включить в работающем чате (например, после утверждения плана), Claude Code запускается с `--allow-dangerously-skip-permissions`. Флаг лишь разрешает переключение, режим задаёт `--permission-mode`. В «Аудите» флага нет.
   - Соответствие у Codex: `untrusted`, `on-request`, `never`.
5. **Вход** выполняется только через официальные потоки вендоров. Платформа учётные данные не читает и не хранит.
   - **Claude Code:** `claude auth login` (подписка) или `claude auth login --console` (оплата по API). Команда набирается в терминале одной кнопкой из чата. Состояние входа берётся из `claude auth status --json`.
   - **Codex:** `account/login/start` с типом `chatgptDeviceCode`. Чат показывает ссылку и код, пользователь подтверждает вход на сайте OpenAI.
6. **Режимы работы платформы в чате:** «Создание», «Разработка», «Модернизация», «Аудит», «Сопровождение».
   - Режим выбирается при создании чата и закреплён за ним (`workflow` в операции `new`). Другой режим — новый чат.
   - Процесс режима передаётся агенту официальными средствами CLI: `--append-system-prompt` у Claude Code, `developerInstructions` у Codex. Там же правило отвечать на языке вопроса.
   - **Согласование.** Режимы, которые меняют код, начинают с плана.
     - Claude Code работает в своём режиме `plan`, пока пользователь не утвердит план. Запрос `ExitPlanMode` приходит в чат карточкой «План работы» с кнопками «Утвердить план» и «Доработать».
     - После утверждения работа идёт в выбранных пользователем разрешениях (`setMode` в ответе на запрос).
     - У Codex режима плана нет. До утверждения действует политика `untrusted`: каждая правка и небезопасная команда требуют разрешения. План утверждается кнопкой «Утвердить план и выполнить» (`send` с `approve_plan`).
     - Утверждение записывается в метаданные чата (`planned`) и событием `planned`.
   - **«Аудит» только читает.**
     - Claude Code запускается без инструментов записи (`--disallowedTools Write Edit MultiEdit NotebookEdit`) в режиме `default`, какие бы разрешения ни выбрал пользователь.
     - Чтение работает без вопросов. Инструменты чтения Claude Code (`Read`, `Grep`, `Glob`) и команды оболочки, которые консервативная проверка признаёт читающими, служба пропускает у обоих агентов.
       - Признаются читающими только известные программы: `cat`, `sed -n`, `grep`, `rg`, `find`, `ls`, `git log/diff/show` и подобные. При этом не должно быть пишущих флагов (`sed -i`, `find -delete/-exec`, `sort -o`, `git --output`…), подстановок `$(…)`, фоновых задач и перенаправлений, кроме как в `/dev/null`.
     - Любой другой запрос разрешения служба отклоняет сама и сообщает об этом в чате (`notice`).
     - После каждого хода служба сравнивает `git status` рабочей области (с хэшами файлов) с состоянием до хода. Если файлы всё же изменились (например, правилом из настроек пользователя), чат показывает предупреждение.
   - Ограничения «Аудита» технические, остальные правила процесса (ветки `ai/…`, тесты, шаги по одному) агент выполняет по инструкции. Их проверяют ревью и тесты проекта.
7. **Несколько экземпляров на одном Docker.** Контейнеры помечаются экземпляром (`ai-coding.workspace.instance`, хэш каталога данных). Каждый экземпляр запускает, отсоединяет и убирает только свои. Контейнер из устаревшего образа заменяется, когда им никто не пользуется. Кнопка «Перезапустить среду» (`POST …/workspace/restart`) заменяет его сразу.

## Последствия

- Разработка в браузере по образцу VS Code: чат, правки с diff, разрешения, история. Агенты работают в фоне в изолированном контейнере пользователя.
- Режимы платформы доступны в чате без настройки LLM на сервере: работу выполняет агент пользователя по процессу режима. Оркестраторы CLI (`ai-coding create`, `develop` и другие) с их артефактами и шлюзами остаются отдельным путём.
- **Правила вендоров.** Чат управляет **неизменённым** официальным CLI в среде пользователя, а вход выполняется официальным потоком вендора. Это ближе всего к сценарию, который Anthropic прямо разрешает: «пользователь входит в неизменённый Claude Code своей подпиской, в том числе когда Claude Code размещён на платформе». Но собственный интерфейс поверх CLI в этих правилах прямо не описан. Для использования всей организацией надёжнее вход через Anthropic Console или API-ключ OpenAI либо письменное подтверждение вендоров.
- Протоколы CLI меняются от версии к версии. Версии в образе закреплены, обновление — пересборка образа с проверкой (`tests/integration/test_workspace_agent.py`, включая тест с настоящим Claude Code против подставного API).

## Альтернативы

- **Только терминал (ADR-0036).** Остаётся для входа и ручной работы, но не похож на привычный чат.
- **Собственный агент платформы через API LLM.** Не использует CLI и подписки, разные функции дублировались бы.
- **Codex через `codex exec --json` на каждый ход.** Отклонено: нет интерактивных одобрений, а app-server даёт полный протокол расширения.
