# ADR-0001: Фиксировать архитектурные решения в ADR

- Статус: Принято
- Дата: 2026-11-05

## Контекст
ТЗ v2.1 требует сохранять архитектурные решения в ADR, а изменения требований — через ADR/Change Request с оценкой влияния на сроки и безопасность. Платформу будут развивать люди и AI-агенты; решения должны быть проверяемыми и воспроизводимыми.

## Решение
- ADR хранятся в `docs/adr/NNNN-kebab-title.md`, нумерация сквозная, номера не переиспользуются.
- Структура: Статус, Дата, Контекст, Решение, Последствия, Альтернативы.
- Принятый ADR не редактируется по существу; пересмотр — новым ADR со статусом `Заменяет ADR-XXXX`.
- PR, меняющий архитектурный инвариант (слои, контракты, схему конфигурации, модель безопасности), обязан ссылаться на ADR.

## Последствия
История решений видна в git; агент Architect (S5) генерирует ADR в том же формате для пользовательских проектов.

## Альтернативы
Wiki/Confluence — отклонено: решения отрываются от кода и не проходят review.
