# ADR-0019: Адаптеры инструментов, нормализованные находки, офлайн-правила Semgrep

- Статус: Принято (реализовано в S3)
- Дата: 2026-11-05

## Контекст
ТЗ §4: запускать реальные бинарные инструменты. FR-06: находки с severity и evidence. NFR-05: воспроизводимость на закреплённых версиях. AUDIT по умолчанию только читает проект (read-only). При `local-only` — никаких сетевых запросов (AC-05).

## Решение
- **Порт `ToolAdapter`:**
  - `spec`: имя, категория, бинарь, образ по digest, стеки, выполняет ли инструмент код проекта, переменные окружения;
  - `version_args` / `parse_version`, `scan_args`, `ok_exit_codes`;
  - `parse` → `Finding`.
- **Нормализованная находка:** tool, rule_id, severity, title, message, path (относительно репозитория), line, fingerprint, evidence. Значения секретов в находки не попадают (gitleaks запускается с `--redact`).
- **Fingerprint** = SHA-256 от (tool, rule, path, *нормализованный якорь содержимого*), без номера строки. Поэтому baseline не ломается от сдвига строк, а меняется при изменении самого кода.
- **Инструменты S3:** Gitleaks 8.30.1 (секреты), Semgrep 1.183.0 (SAST), Ruff 0.16.9 (lint Python). Версии фиксируются digest'ом образа и записываются в отчёт.
- **Офлайн-набор правил Semgrep** `ai_coding/tools/rules/semgrep/ai-coding-baseline.yml`: 13 правил, написанных для проекта (Python, JS/TS/React, PHP/Laravel, Go, Rust). Конфигурации из реестра (`auto`, `p/…`, `r/…`, URL) отклоняются: им нужна сеть. Свои правила подключаются через `--semgrep-config`. Каждое правило проверено тестом на позитивном примере (`tests/fixtures/semgrep`).
- **Телеметрия и проверки обновлений отключаются** (`--metrics=off`, `--disable-version-check`, `SEMGREP_SEND_METRICS=off`). Найдено при реализации: `semgrep --version` без `--disable-version-check` зависает в песочнице без сети. Для проверки версии введён отдельный короткий таймаут (60 с).
- **Политика (новое правило `tools.read_only_analysis`):** на хосте разрешены зарегистрированные инструменты анализа, которые только читают проект; инструменты, выполняющие код проекта (тесты, сборка), подчиняются правилам `execution.allow_host_commands`. В песочнице разрешено всё.
- **Fail closed:** если инструмент не запустился, завис, выдал слишком много вывода или вывод не разбирается, `ToolRun.succeeded = false`, и гейт, который от него зависит, получает FAIL с причиной. Отсутствие результата не считается «находок нет».

## Последствия
Новый инструмент — это адаптер, образ по digest и тест разбора вывода. Адаптеры для PHP, JS/TS, Go, Rust, Trivy/OSV, Playwright и k6 — S7.
