# ADR-0025: DEVELOP — цикл «реализация → тесты → review», тесты в песочнице, рекомендательный review

- Статус: Принято
- Дата: 2026-11-05
- Спринт: S6 (B-500…B-503, B-506, B-507)

## Контекст
- FR-04: Issue → план → ветка → patch → тесты → review → PR.
- AC-03: функция в отдельной ветке, тесты выполнены, PR без прямого push в main.
- ТЗ §10: AI review рекомендателен.
- ТЗ §12: код агента недоверенный, исполнение только в изоляции.
- ТЗ §18: повреждение репозитория предотвращается worktree, отдельной веткой и rollback.
- Правило проекта: каждая задача сопровождается тестами.

## Решение
1. **Формат изменений.** Developer Agent возвращает **полное новое содержимое** файлов (`create`/`modify`/`delete`), а не diff:
   - LLM нередко ломают unified diff;
   - полное содержимое применяется ровно и проверяется по хэшу.

   Семантические проверки выполняет `agents/developer.py`. Если агент правит файл, который видел не полностью, файл добавляется в контекст и вызов повторяется.

   | Проверка | Что требуется |
   | --- | --- |
   | Пути | относительные, без `..`, не внутри `.git/` и `.ai-coding/` |
   | `create` | файла ещё нет в репозитории |
   | `modify` / `delete` | файл существует |
   | `modify` | содержимое действительно изменено |
   | Тесты | хотя бы один тестовый файл добавлен или изменён (отключается только явно) |
2. **Цикл** (`workflows/implement.py`), не больше `max_iterations` (по умолчанию 3) и в пределах бюджета прогона (B-503). Каждая итерация:
   - выгружает базовый коммит (`git archive`) во временный каталог;
   - применяет изменения к копии;
   - запускает тесты в песочнице;
   - отдаёт diff на review (Reviewer) и, если затронуты миграции, на анализ (Database Agent).

   Обратная связь следующей итерации — вывод упавших тестов и critical/high замечания review.

   Репозиторий и рабочая копия пользователя в цикле **не меняются**. Каждая итерация сохраняется как артефакт.
3. **Тесты в Docker-песочнице** (`tools/testrun.py`):
   - Дерево **копируется**; копия — единственный записываемый mount.
   - Контейнер:
     - без сети;
     - с read-only root;
     - без capabilities;
     - запускается не от root.
   - Шаг установки зависимостей — единственный, которому может понадобиться сеть. Он разрешён, только если `execution.docker.network: bridge` **и** egress-политика разрешает нужные хосты (pypi.org, registry.npmjs.org). Иначе тесты получают статус SKIPPED с причиной.
   - Образы рантаймов закреплены по digest и скачиваются явно (`ai-coding tools pull`). Источник — официальный зеркальный реестр `mirror.gcr.io`: Docker Hub ограничивает частоту запросов, а digest фиксирует содержимое образа независимо от реестра.
   - Если образа нет или Docker недоступен, тесты получают SKIPPED с инструкцией.
4. **Приёмка изменения.**
   - Тесты должны быть PASSED. SKIPPED допустим только без `--strict`.
   - В MODERNIZE при зелёном baseline разрешён только PASSED.
   - Review **рекомендателен**: critical/high замечания запускают следующую итерацию. После последней итерации они блокируют изменение только при явной политике `quality_gates.review.ai_review_blocking`.
5. **Фиксация изменений.**
   - Принятый набор изменений коммитится **один раз**: в отдельном worktree, на новой рабочей ветке, с trailer `AI-Coding-Run`. Существующая ветка не перезаписывается.
   - Повтор или resume находит коммит через журнал эффектов и trailer.
   - Удаления требуют approval `delete`; критичные файлы — approval `critical_file_change`.
6. **`develop.verify`** перечитывает каждый файл из коммита, сверяет хэши и заново запускает тесты на дереве коммита. PR открывается только после этой проверки.
7. **PR.** Описание PR содержит:
   - сводку;
   - список изменений;
   - результат тестов;
   - замечания review;
   - `Closes #N`.

   Merge платформа не выполняет.
8. **`ai-coding review` и `ai-review.yml`.**
   - Reviewer проверяет diff `base…head`.
   - Результат публикуется как комментарий (upsert) и check run.
   - Conclusion check run — `neutral`. `failure` ставится только при блокирующей политике.
   - Ключ LLM хранится в секретах environment (с approval).
   - Для PR из форков review не запускается, пока явно не разрешён; даже тогда записи в PR не выполняются.
9. **Движок.** Пауза на approval или по бюджету больше не тратит попытку задачи (исправление проблемы из S5).

## Последствия
- **Плюс:** каждое изменение агента проверено настоящими тестами в изоляции до коммита. Коммитится ровно то, что проверено.
- **Минус:** полное содержимое файла увеличивает расход токенов на больших файлах. Контекст ограничен 24 тыс. токенов, файлы больше 200 КБ не индексируются.
- **Ограничение:** Python-проектам для pytest нужен шаг установки, то есть сеть. Офлайн можно задать свою команду, например `python -m unittest`. Адаптеры стеков (S7) расширят набор команд по умолчанию.
