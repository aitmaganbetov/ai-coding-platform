# ADR-0027: Инструменты стеков проекта и офлайн-данные инструментов

- Статус: Принято
- Дата: 2026-11-05
- Спринт: S7 (B-600, B-601, B-602, B-225, follow-up B-210)

## Контекст
AUDIT должен работать для Laravel+React, Go, Rust, Python и Node (AC-02, ТЗ §10). Анализаторы S3 (Gitleaks, Semgrep, Ruff) читают только исходники. Инструментам стеков (PHPStan, Pint, ESLint, `tsc`, mypy, `go test`, golangci-lint, `cargo test`, Clippy) нужны зависимости проекта (`vendor/`, `node_modules/`, модули, crates), а тестам — ещё и выполнение кода проекта. Сканерам уязвимостей (Trivy, OSV-Scanner) нужны базы уязвимостей. Аудит при этом должен оставаться офлайн и read-only (FR-06, AC-05).

## Решение
1. **Два вида инструментов в одном реестре.**
   - `ToolAdapter` (S3): самодостаточные анализаторы — Gitleaks, Semgrep, Ruff, Trivy, OSV-Scanner.
   - `ProjectTool` (S7): `plan(root) → Invocation | причина`, `ok_exit_codes`, `parse`, `parse_version`, опционально `coverage`.

   Реестр выбирает инструменты по стекам. Сторонние адаптеры подключаются через группу entry points `ai_coding.tools`.
2. **`ProjectTool` работает только в Docker-песочнице.** На хосте и в backend `local` инструмент получает SKIPPED с причиной: он выполняет код проекта.
   - Проект монтируется **только для чтения** в `/work`.
   - Если нужна установка зависимостей или инструмент пишет в дерево (`Cargo.lock`, сборка Go), используется **копия** (без `.git`, `vendor`, `node_modules`, `target`, до 500 МБ). Репозиторий не меняется.
   - `/deps` — изменяемый том для кэшей, хранилищ модулей и сборки (`/tmp` смонтирован с `noexec`).
3. **Установка зависимостей — единственный шаг с сетью.** Нужно и `execution.docker.network: bridge`, и разрешение egress-политики для каждого хоста реестра (Packagist, npm, PyPI, Go proxy, crates.io). Иначе инструмент SKIPPED с точной причиной. Скрипты пакетов отключены (`--no-scripts`, `--no-plugins`, `--ignore-scripts`).
4. **Неприменимый инструмент — SKIPPED, сломанный — FAIL.**
   - Нет манифеста, конфигурации или зависимости → SKIPPED с причиной.
   - Инструмент запустился, но не дал результата (неожиданный код выхода, таймаут, обрезанный вывод, ошибка разбора, сбой установки) → гейт FAIL (fail-closed, ADR-0020).
   - Гейт, где все инструменты SKIPPED, тоже SKIPPED, а причина перечисляет инструменты. `--strict` превращает такой гейт в FAIL.
5. **Покрытие.** Тестовые инструменты сообщают покрытие (`go test -cover`). Гейт Coverage сравнивает минимальное значение с `quality_gates.coverage.min_percent`.
6. **Офлайн-данные в кэше платформы**: `$AI_CODING_CACHE_DIR`, иначе `~/.cache/ai-coding`. Кэш никогда не лежит внутри проекта.
   - Заполняет его только явная команда `ai-coding tools pull` — сетевое действие пользователя, как скачивание образов. Подготовка идёт в образе самого инструмента под непривилегированным пользователем, смонтирован только кэш.
   - Содержимое: БД Trivy, БД OSV по экосистемам (через seed-lockfile), toolchain Rust с Clippy (в slim-образе Clippy нет).
   - При сканировании кэш монтируется в `/cache` или `/toolchain`. Монтирование изменяемое: bbolt пишет lock-файл, но проект при этом не меняется.
   - Если данных нет, инструмент SKIPPED с подсказкой `tools pull -t X`.
7. **Воспроизводимость (NFR-05).** В отчёте для каждого инструмента: версия, digest образа, снимок данных (`db_version`, `db_updated_at`). Fingerprint находки не зависит от времени и порядка. Тест AC-02 проверяет, что два аудита дают одинаковые находки.
8. **Подавления на уровне инструментов (B-225).** `.semgrepignore`, `.gitleaksignore`, `.trivyignore`, `osv-scanner.toml`, `phpstan-baseline.neon` и inline-маркеры (`nosemgrep`, `gitleaks:allow`, `eslint-disable`, `@phpstan-ignore` …) обходят baseline платформы: у них нет владельца и срока. Отчёт их перечисляет. Отдельно раскрывается неявный список игнорирования Semgrep по умолчанию (`tests/`, `vendor/` …).
9. **Запуск инструмента в образе.** По умолчанию — имя бинарника как entrypoint. Если в образе бинарник не в `PATH`, адаптер задаёт `sandbox_entry`. Так сделано для OSV: в Dockerfile `ENTRYPOINT /osv-scanner`, а бинарник копируется в WORKDIR базового образа.

## Последствия
- **Плюс:** аудит Laravel+React находит SAST-, секретные, зависимостные и конфигурационные проблемы офлайн, с путями файлов, и не меняет репозиторий.
- **Плюс:** без сети инструменты, которым нужны зависимости, честно SKIPPED с причиной — результат не подделывается.
- **Ограничение:** чтобы PHPStan, Pint и ESLint работали на проекте без `vendor/` и `node_modules/`, нужна политика с egress к реестрам и `network: bridge`.
- **Ограничение:** `tools pull` скачивает несколько ГБ (образы, БД Trivy, toolchain Rust). CI на это рассчитан.
- **Отложено:** B-603 (Playwright, k6) требует запущенного приложения и сети. Перенесено в S9 (нагрузочные и E2E-тесты). Performance Agent уже анализирует переданные результаты k6 или APM.
