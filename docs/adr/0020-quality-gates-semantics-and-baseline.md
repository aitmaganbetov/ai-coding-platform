# ADR-0020: Семантика Quality Gates и формат baseline

- Статус: Принято (реализовано в S3)
- Дата: 2026-11-05
- Уточняет: ADR-0012

## Контекст
ТЗ §10: гейты Build, Tests, Static, Security, Coverage, Review с результатами PASS, FAIL и SKIPPED; baseline существующих проблем — с исключениями, владельцем и сроком действия.

## Решение
- **Гейт вычисляется только из `ToolRun`** реальных инструментов, по категориям: SECRETS, SAST, DEPENDENCIES → Security; LINT, TYPES → Static; BUILD → Build; TESTS → Tests.
- **Security** = FAIL, если есть новая находка с severity не ниже `fail_on` или новый секрет (при `block_new_secrets`). **Static** = FAIL, если новых находок больше `max_errors`.
- **SKIPPED** — с явной причиной: «гейт выключен», «нет применимого инструмента (адаптеры: S7)», «нет изменения на ревью». По умолчанию SKIPPED не делает вердикт FAIL. С `--strict` (`ai-coding audit --strict`) SKIPPED у блокирующего, но включённого гейта означает FAIL. Это пересмотр ADR-0012: иначе любой audit до S7 был бы FAIL из-за отсутствия адаптеров для тестов и сборки, то есть FAIL не по существу.
- **Fail closed:** сломанный инструмент → FAIL гейта (ADR-0019).
- **Вердикт** = FAIL, если FAIL хотя бы у одного *блокирующего* гейта (или сработал strict); иначе PASS. Неблокирующий FAIL виден в отчёте, но вердикт не меняет.
- **Baseline** — файл `.ai-coding-baseline.json` в корне репозитория. Он коммитится, поэтому изменения проходят ревью. Состав записи: `fingerprint`, `tool`, `rule_id`, `path`, `owner`, `reason`; `expires_at` обязателен. Записи с истёкшим сроком **перестают подавлять** находки, и те снова влияют на гейты (баг найден тестом S3). `ai-coding baseline create REPORT --owner --reason --expires` создаёт baseline из отчёта аудита для внедрения на существующем проекте; дата в прошлом отклоняется.

## Последствия
AC-06: человек видит причину каждого гейта и доказательства — список `tool:rule path:line (severity)`, до 50 строк на гейт; полный список — в JSON-отчёте.
