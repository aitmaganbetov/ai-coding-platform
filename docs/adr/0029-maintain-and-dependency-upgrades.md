# ADR-0029: MAINTAIN — triage, утверждённый план, обновление зависимостей пакетным менеджером

- Статус: Принято
- Дата: 2026-11-05
- Спринт: S7 (B-610, B-612)

## Контекст
FR-07 и ТЗ §3 требуют triage, обновления зависимостей и регрессионные тесты. Lock-файл (разрешение версий, хэши целостности) должен быть настоящим: модель не должна его писать. Обновление зависимости — сетевое действие, и оно должно подчиняться политике.

## Решение
1. **Источники** — недоверенные данные для агента:
   - issues: GitHub `--issue N` или файл `--issues-file`;
   - находки и уязвимые зависимости из отчёта аудита `--report audit-report.json`. Уязвимости Trivy и OSV группируются по пакету, версии и lock-файлу, исправленные версии объединяются;
   - телеметрия `--telemetry`.
2. **DAG:**
   - `maintain.baseline` (тесты базы; красный baseline останавливает прогон);
   - `maintain.plan` (Maintenance Agent);
   - `maintain.approve` (человек утверждает версию `m-<sha8>`; это plan approval, как в MODERNIZE);
   - `maintain.deps`;
   - `maintain.item`;
   - `maintain.verify`;
   - PR (опционально).

   Один прогон выполняет одну задачу. Задачи идут по приоритету p0 → p3. Следующую задачу утверждённого плана запускает `--continue RUN [--item ID]`, без нового плана и без повторного утверждения.
3. **`maintain.deps`** — обновление делает пакетный менеджер экосистемы в песочнице:

   | Экосистема | Команда |
   | --- | --- |
   | npm | `npm install pkg@v --package-lock-only --ignore-scripts` |
   | Packagist | `composer require pkg:v --no-install --no-scripts --no-plugins` |
   | Go | `go get mod@v` |
   | crates.io | `cargo update -p pkg --precise v` |
   | PyPI | закрепление версии в `requirements.txt` без сети |

   - Работает на копии каталога манифеста; наружу выходят только манифест и lock-файл.
   - Версия обязана входить в список исправленных версий от сканера. Имя и версия проверяются, чтобы их нельзя было подставить как аргументы.
   - Сеть только при `network: bridge` и разрешении egress для хостов реестра.
   - Конфликт разрешения (например, composer: «conflicts with your root composer.json») останавливает задачу и показывает причину. Никаких «обходных» правок.
4. **`maintain.item`** — цикл S6 начинается с изменений пакетного менеджера (`seed`) и включает их в принятый набор изменений.
   - Developer обязан добавить или обновить названный регрессионный тест и не трогает lock-файлы.
   - Если baseline зелёный, требуется PASSED (strict).
   - Изменение lock-файлов `*.lock` подпадает под `critical_paths` и требует approval.
5. Описание PR содержит задачу, источники, регрессионный тест и обновления. Merge выполняет человек.

## Последствия
- **Плюс:** обновления воспроизводимы и честны — lock-файл создаёт сам пакетный менеджер. Каждое исправление идёт отдельной маленькой веткой или PR с тестом.
- **Ограничение:** для обновления нужна сеть к реестру. При `network: none` задача получает FAILED с понятной причиной.
- **Ограничение:** проверка «сканер больше не находит уязвимость» — пока отдельный `ai-coding audit` на ветке (follow-up S9).
