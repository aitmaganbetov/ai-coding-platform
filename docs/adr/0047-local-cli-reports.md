# ADR-0047: Local (CLI) — прогоны с машин разработчиков на сервере

- Статус: Принято
- Дата: 2026-11-06
- Уточняет: [ADR-0030](0030-server-api-rbac-queue.md), [ADR-0039](0039-nexus-web-ui.md)

## Контекст

`ai-coding` на машине разработчика работает автономно: своя SQLite в `.ai-coding/`, никаких обращений к серверу. Поэтому на странице «Инфраструктура» карточка «Local (CLI)» показывала только «не наблюдается». Команда не видела, кто и с каким результатом гоняет аудиты и задачи локально.

Требования:
- подключить CLI к серверу без смены режима работы: локальные прогоны остаются локальными, сервер получает сведения о них;
- не отправлять код, пути файлов и тексты находок: аудит часто запускают ради проверки ещё не опубликованного кода;
- не ломать команду, если сервер недоступен;
- подключение настраивается за минуту, токен берётся в Web UI.

## Решение

1. **Вход.** `ai-coding server login --url URL` спрашивает API-токен пользователя (Web UI → «Аккаунт → Токены»), проверяет его запросом `GET /me` и сохраняет URL и токен в `~/.config/ai-coding/server.json` с правами `0600`. Для CI вместо файла можно задать `AI_CODING_REMOTE_URL` и `AI_CODING_REMOTE_TOKEN`. Для адреса без HTTPS (кроме localhost) CLI предупреждает, что токен идёт открытым текстом.
2. **Привязка каталога.** `ai-coding server link ПРОЕКТ` (имя или id из `GET /projects`) записывает привязку в `.ai-coding/server.json` проекта. Этот каталог сам себя исключает из git, поэтому привязка никогда не попадает в коммит. Переменная `AI_CODING_REMOTE_PROJECT` переопределяет привязку.
3. **Отчёт.** Все команды CLI закрывают оркестраторы через `close_all()`. Там отправляются прогоны локальной базы, изменённые за время команды (`runs.updated_at` не раньше момента открытия), и только при наличии и входа, и привязки. Отчёт — сводка:
   - режим, цель (до 200 символов, через редактор секретов), состояние, ошибка;
   - вердикт, гейты и число новых находок по уровням (из `audit-report.json`, только для аудита);
   - ветка, коммит, машина, версия CLI, время начала и конца, число задач по статусам.

   Ошибка отправки — предупреждение в stderr с подсказкой `ai-coding server report <id>`. Код выхода команды не меняется, stdout (`--json`) остаётся чистым.
4. **Сервер.** Таблица `local_runs` (миграция `0005_local_runs`) с уникальным ключом (`project_id`, `run_id`). Повторный отчёт о том же прогоне обновляет строку, а не дублирует её.
   - `POST /projects/{id}/local-runs` — право `run.create`. Строку, созданную одним пользователем, другой перезаписать не может (409). Каждый отчёт пишется в журнал аудита (`local_run.report`).
   - `GET /projects/{id}/local-runs` — право `run.view`.
   - `GET /local-runs/overview` — машины и пользователи за 30 дней в доступных вызывающему проектах, их последний отчёт и число отчётов за сутки. Отсюда берёт данные карточка «Local (CLI)».

   Проверка прав идёт до разбора тела: посторонний получает 404, а не 422.

## Последствия

- Имя машины — то, что сообщил CLI; это метка, а не удостоверение. Личность определяет токен.
- Сервер не хранит находки локальных прогонов и не может их показать — только счётчики. Для полной картины нужен аудит на сервере.
- Прогоны до входа и привязки не отправляются задним числом. Отдельный прогон можно отправить командой `ai-coding server report`.
- Отчёты не хранятся в одном журнале аудита: журнал только дописывается, а повторный отчёт должен обновлять строку. В журнал попадает лишь факт отчёта.
