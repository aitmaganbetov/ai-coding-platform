# ADR-0032: Приёмочная матрица, нагрузочные и security-тесты перед релизом

- Статус: Принято
- Дата: 2026-11-05

## Контекст

ТЗ §20 разрешает выпускать v2.1 только после прохождения всех AC-01…AC-10. В S9 также требуются нагрузочные тесты API и worker'ов (B-800, NFR-02) и security-тесты (B-801):
- SAST/DAST API;
- fuzzing конфигурации;
- попытки выхода из песочницы.

К началу S9 сценарии AC существовали как отдельные тесты, но ни один процесс не проверял, что пройдены **все** AC, и пропуск выглядел как успех. Сценариев для AC-05, AC-06 и AC-09 не было.

## Решение

1. **Приёмочная матрица — часть тестов, а не документа.**
   - Сценарий помечается `@pytest.mark.acceptance("AC-NN")`. Плагин `tests/acceptance_plugin.py` с `--acceptance-report` строит JSON и Markdown.
   - Прогон завершается ошибкой, если у AC нет сценария, сценарий упал или **пропущен**: пропуск не считается приёмкой.
   - Матрица строится в CI-job sandbox на каждом push и PR и попадает в summary.
   - Недостающие сценарии:
     - AC-05 — записываются все соединения процесса и сеть каждого контейнера песочницы;
     - AC-06 — сравнение базовой ветки и PR, проверка check run с аннотациями и комментария;
     - AC-09 — тест читает `pilots.yml` и делает то же, что reusable workflows;
     - AC-10 — на изменяющей операции `pr open`.

2. **Нагрузочный тест — сервер в форме production.**
   - `loadtest/run_load.py` поднимает PostgreSQL, `serve --workers 2` и два процесса worker'ов. k6 (образ по digest) выполняет `loadtest/server.js`.
   - Пороги:
     - ≥ 10 одновременных прогонов: `aicoding_jobs{state="leased"}` по всем worker'ам;
     - все прогоны завершены;
     - ошибок < 1 %;
     - p95 чтения < 500 мс.
   - Профиль по умолчанию реалистичный: опрос раз в секунду; UI опрашивает каждые 2 с. Перегрузочный профиль включается флагами и служит для измерения предела.
   - CI-job «Load test (k6)».

3. **Security-тесты строятся от поверхности, а не от списка.**
   - Проверка прав берёт маршруты из OpenAPI самого приложения: новый endpoint без аутентификации или изоляции падает автоматически.
   - Schemathesis генерирует для каждой операции корректные (positive) и некорректные (negative) запросы. Требования: нет 5xx, есть заголовки безопасности, единый формат ошибок.
   - Hypothesis подаёт на вход валидатора конфигурации произвольный текст, документы и мутации. Принятая конфигурация обязана сохранять инварианты `local-only` и `audit`.
   - 26 проб изнутри песочницы проверяют привилегии, namespaces, устройства, файловую систему, лимиты и сеть.
   - Property-тест проверяет redaction всех типов секретов в любом окружении.
   - SAST репозитория по-прежнему выполняет самоаудит: gitleaks и Semgrep в песочнице.

4. **Найденное — исправляется в том же спринте и закрепляется тестом:**
   - DoS через YAML-«billion laughs»: загрузчик измеряет размер документа после раскрытия алиасов на составленном графе и отказывает при > 100 000 узлов;
   - ошибки фреймворка шли мимо единого формата;
   - токены `aic_` не скрывались в логах;
   - `local-only` пропускал внешний `base_url` у «локального» провайдера: теперь он проверяется в конфигурации, а адрес — при каждом запросе к модели: клиент сам разрешает имя и подключается к проверенному адресу, так что DNS rebinding не уводит запросы наружу;
   - разбор YAML и JSON Schema на каждый запрос к прогону: добавлен кэш по mtime и размеру;
   - один процесс API (GIL): добавлен `serve --workers N`;
   - размер пула соединений: параметр и правило расчёта.

## Последствия

- Релиз определяется зелёной матрицей, а не впечатлением. В отчёте спринта — фактическая матрица из CI.
- Предел одного процесса API — около 200 запросов в секунду на ядро. Масштабирование — `serve --workers N` и отдельные хосты worker'ов (ADR-0034).
- **DAST сторонним сканером (HawkScan, OWASP ZAP) не выполнялся:** нет ключа HawkScan, образ ZAP недоступен в среде разработки. Schemathesis и проверка прав по всей поверхности покрывают API-специфичные классы. Сканер общего назначения — рекомендация для эксплуатации ([runbook](../runbook.md)).

## Альтернативы

- **Список приёмки в документе без автоматической проверки** — отклонено: устаревает и не ловит пропуски.
- **Locust вместо k6** — отклонено: k6 указан в ТЗ и уже используется для проектов пользователей (B-603).
