# ADR-0045: Вкладки редактора, Split View и вкладки рабочих областей

- Статус: Принято
- Дата: 2026-11-06
- Уточняет: [ADR-0041](0041-ai-in-the-editor.md)

## Контекст

В Code Studio и на вкладке Code в AI Workspace был открыт один файл. Другой файл из дерева заменял его, а несохранённые правки терялись из вида. Два файла рядом (код и тест, интерфейс и реализация) посмотреть было нельзя.

Ссылки на место в коде (результаты тестов, находки аудита) открывали только Code Studio. Нужный файл и строку пользователь искал сам.

Между проектами и между AI Workspace и Code Studio переходили через меню. Если работаешь в нескольких проектах, это каждый раз несколько шагов. Боковое меню, командная строка и панели рабочей области занимают место, которое при правке кода нужно редактору.

## Решение

1. **Вкладки редактора** — в Code Studio и на вкладке Code в AI Workspace (общий компонент).
   - Файл из дерева открывается вкладкой рядом с активной. Уже открытый файл просто показывается.
   - У вкладки с несохранёнными правками стоит точка ●. Закрыть такую вкладку (× или средняя кнопка мыши) можно только после подтверждения.
   - Неактивные вкладки остаются в DOM скрытыми. Их текст, история отмены и прокрутка переживают переключение.
   - Если редактор уходит с экрана целиком (вкладка Chat в AI Workspace, «Изменения» в Code Studio), его несохранённый текст становится исходным для нового редактора: CodeMirror пересоздаётся с этим текстом.
   - Каждая вкладка ведёт себя как прежний одиночный редактор:
     - сохранение с проверкой версии и конфликтом;
     - удаление файла;
     - перечитывание после изменений агента (только для вкладок без несохранённых правок);
     - ИИ в редакторе по ADR-0041: отметки изменений, «Принять/Отклонить», действия над выделением.
   - Вкладки проекта запоминаются в браузере (`localStorage`, ключ `nexus-tabs-<проект>`). Хранятся только пути и раскладка групп, содержимое файлов — никогда.
   - При открытии проекта вкладки возвращаются, а файлы загружаются, когда их вкладка показана. Вкладка удалённого файла закрывается молча.
   - В группе не больше 20 вкладок.
   - Ctrl+W не перехватывается: браузер оставляет это сочетание за собой и закрывает свою вкладку.
2. **Split View** — до двух групп редактора, у каждой свои вкладки.
   - «Разделить редактор» переносит активную вкладку в правую группу. Если вкладка одна, открывается пустая правая группа.
   - «Открыть справа» и «Открыть слева» переносят вкладку в другую группу. «Объединить группы» собирает все вкладки в одну.
   - Новые файлы открываются в группе, где пользователь работал последним (она выделена рамкой).
   - Границу между группами можно тянуть мышью или двигать стрелками на 5%. Доля левой группы — от 20 до 80%, запоминается.
   - Опустевшая группа закрывается.
   - Уже 900 px группы не помещаются рядом. Показывается одна, переключатель «Левая группа / Правая группа» стоит над редактором.
3. **Один файл — одна группа.** Файл открыт только в одной группе. «Открыть справа» переносит вкладку вместе с несохранёнными правками, а не создаёт копию. Если открыть из дерева файл, который уже есть в другой группе, он покажется там.
   - Причина: два редактора одного файла — это два состояния CodeMirror с разными историями отмены. Правки разошлись бы, и неясно было бы, какую версию сохранять.
   - Отметки ИИ и «Принять/Отклонить» работали бы только в одной копии.
   - Синхронизация двух редакторов на каждое нажатие требует общей модели документа, которой в CodeMirror 6 нет. Задачу «два файла рядом» решение закрывает и без этого.
4. **Открыть файл на строке.** Ссылка `#/projects/<id>/code?file=<путь>&line=<n>` (`href("code", id, { file, line })`) открывает файл в Code Studio.
   - Курсор встаёт на строку, строка оказывается в центре и подсвечивается до следующего перехода.
   - `line` можно не указывать.
   - Ссылка с другой строкой того же файла снова переводит курсор.
   - CodeEditor получил свойства `line` и `lineKey`.
5. **Вкладки рабочих областей** — полоса над содержимым страницы.
   - На каждой вкладке — проект и «AI Workspace» или «Code Studio». Недавние идут первыми, вкладок не больше восьми.
   - Список хранится вместе с настройками интерфейса в `localStorage` (`nexus-ui`).
   - Нажатие переключает рабочую область, × закрывает вкладку. Если закрыта текущая, открывается следующая, а если вкладок не осталось — выбор проекта для AI Workspace или Code Studio.
   - Текущая вкладка выделена (`aria-current="page"`). Полоса видна, когда открыта хотя бы одна рабочая область.
   - Выше 1024 px рабочая область занимает высоту, которую оставляет полоса. Сама страница при этом не прокручивается.
6. **Во весь экран** — кнопка в шапке рабочей области.
   - Скрывает боковое меню, командную строку, Copilot, полосу вкладок и боковые панели рабочей области. На экране остаётся основная панель с редактором.
   - Выход — той же кнопкой или Esc. Esc внутри редактора, палитры команд и диалогов остаётся за ними: закрывает подсказки, выделение, сами диалоги.
   - Режим есть только в рабочих областях. Он выключается, когда пользователь уходит из рабочей области или спрашивает ИИ о выделенном коде (нужен чат).

Правила вкладок и групп собраны в чистых функциях `web/src/editorTabs.ts` и проверяются отдельно от интерфейса.

## Последствия

- Несколько файлов открыты одновременно, два видны рядом. Несохранённые правки не теряются при переключении вкладок и переносе между группами.
- Ссылки из результатов тестов и находок ведут к файлу и строке.
- Переход между проектами и режимами — одно нажатие. Для правки кода есть экран без лишнего.
- Вкладки и раскладка хранятся в браузере. На другом устройстве или после очистки данных сайта их нет. Содержимое файлов в `localStorage` не попадает.
- Скрытые вкладки держат свои редакторы в памяти. Поэтому в группе не больше 20 вкладок.
- Проверки:
  - `web/src/workspace.test.tsx`: правила групп, вкладки, подтверждение закрытия, восстановление, Split View, переход на строку, вкладки рабочих областей, полный экран;
  - `web/e2e/split.mjs` — в браузере с настоящей рабочей областью.

## Альтернативы

| Вариант | Почему нет |
| --- | --- |
| Один файл в двух группах с общей моделью (как в VS Code) | Нужна своя синхронизация двух состояний CodeMirror: правки, история отмены, отметки ИИ. Это сложно и рискованно, а главную задачу — два разных файла рядом — закрывает и перенос вкладки. |
| Тот же файл во второй группе только для чтения | Пользователь не понимает, почему справа нельзя править. При правке слева копию справа всё равно надо обновлять. |
| Хранить вкладки на сервере | Нужны новая таблица и API, а пользы мало: вкладки — состояние этого браузера. Пути к файлам не уходят с устройства. |
| Перехватывать Ctrl+W | Chrome не даёт странице перехватить Ctrl+W. Поведение было бы разным в разных браузерах. |
| Больше двух групп и вертикальное деление | Экран рабочей области уже делят дерево и чат. Третья группа помещается только на очень широких мониторах. |
