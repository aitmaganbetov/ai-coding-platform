# ADR-0018: Реализация исполнителей — Docker CLI, `--pull never`, ограничения хоста

- Статус: Принято (реализовано в S3)
- Дата: 2026-11-05
- Уточняет: ADR-0007

## Контекст
ADR-0007 задал единый порт `Executor` и три бэкенда. При реализации S3 нужно было выбрать способ управления Docker, определить, как задаются лимиты на хосте, и закрыть неявный выход в сеть.

## Решение
1. **Docker через CLI, а не через Docker SDK.** `docker run` вызывается списком аргументов (`argv`), без shell. Так проще аудировать: полный набор флагов виден в `DockerSandboxExecutor.build_argv()` и проверяется тестом. Не нужна Python-зависимость и прямой доступ к сокету из процесса платформы. Подход тот же, что у git-адаптера (ADR-0008).
2. **Обязательные флаги песочницы:** `--network none` (сеть только по политике), `--read-only`, `--cap-drop ALL`, `--security-opt no-new-privileges`, `--user 1000:1000`, `--pids-limit`, `--cpus`, `--memory` = `--memory-swap`, `--tmpfs /tmp` (noexec, с лимитом размера), bind-монтирования только для чтения. Запрещены: `--privileged`, монтирование Docker socket (явная проверка), образы без digest.
3. **`--pull never`.** Контейнер никогда не скачивает образ неявно. Скачивание демоном — это тоже выход в сеть, и при `security.network: local-only` его быть не должно (AC-05). Образы загружаются отдельной явной командой `ai-coding tools pull`. Если образа нет, ошибка подсказывает эту команду.
4. **Local Executor:**
   - запускать можно только исполняемые файлы из allow-list, путь разрешается в абсолютный через `PATH`;
   - переменные окружения собираются заново из allow-list (без `*_API_KEY` и прочего);
   - `stdin` закрыт; вывод ограничен по размеру и проходит redaction;
   - при таймауте или отмене убивается вся группа процессов (POSIX `killpg`, Windows `taskkill /T`).
5. **rlimits на POSIX:** CPU, размер файла, число открытых файлов, без core-дампов. **`RLIMIT_AS` не используется:** он ограничивает *виртуальное* адресное пространство, которое Go, JVM и Node резервируют с запасом, и gitleaks падает при старте (найдено при реализации). Настоящие лимиты памяти требуют cgroups, то есть Docker-бэкенда.

## Последствия
- Аудит в Docker-песочнице полностью офлайн после `ai-coding tools pull` (проверено тестом: `wget` изнутри контейнера не проходит, корень и `/src` только для чтения, `CapEff = 0`).
- На Windows лимиты Local Executor — только таймаут и размер вывода; Job Objects — backlog B-206.
- GitHub Actions executor — S4.

## Альтернативы
- Docker SDK для Python — отклонено (см. п. 1).
- gVisor и Firecracker — усиление для Self-Hosted, S9 (B-805).
