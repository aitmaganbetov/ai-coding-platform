# ADR-0017: Структурированное журналирование

- Статус: Принято (реализовано в S2)
- Дата: 2026-11-05

## Контекст
NFR-07: логи без секретов, структурированные метрики и trace/run_id. ТЗ §12: секреты не попадают в логи.

## Решение
- `structlog`, вывод JSON Lines в stderr (человекочитаемый рендерер — опционально).
- Процессор redaction применяется к **каждому** строковому значению события, включая вложенные структуры, до рендеринга.
- `bind_run(run_id)` через contextvars добавляет `run_id` и `trace_id` ко всем строкам в пределах выполнения run (включая параллельные задачи asyncio).
- Поток вывода определяется в момент записи, а не при настройке: если `sys.stderr` подменили или закрыли, это не ломает журналирование, а сбой логирования никогда не должен ронять run. Ошибка найдена тестами S2.
- Аудит (`audit_events`) хранится отдельно от логов: он неизменяемый, лежит в БД и пишется в той же транзакции, что и изменение, которое он фиксирует.

## Альтернативы
Стандартный `logging` с JSON-форматтером — отклонено: нет удобной привязки контекста run для asyncio-задач.
