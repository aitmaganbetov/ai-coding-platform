# ADR-0016: Аренда (lease) прогона и журнал эффектов для восстановления

- Статус: Принято (реализовано в S2)
- Дата: 2026-11-05
- Дополняет: ADR-0006

## Контекст
AC-04: при падении worker'а run должен возобновляться **без дублирования коммитов**. NFR-03: сбой исполнителя не теряет подтверждённые состояния. Процесс может быть убит в любой момент, в том числе между «сделали коммит» и «записали, что сделали».

## Решение
1. **Lease вместо блокировок в памяти.** Исполняющий worker атомарно захватывает `runs.lease_owner/lease_expires_at` (`UPDATE … WHERE lease свободен или истёк`) и продлевает его heartbeat'ом каждые `ttl/3`. Упавший worker перестаёт продлевать lease, и после истечения TTL любой другой worker может выполнить `resume`. Если lease отобрали, worker останавливается без переходов состояния. `--force` позволяет забрать живой lease, но CLI требует подтверждения, потому что так шаг может выполниться дважды.
2. **Попытка задачи фиксируется до запуска.** Статус `RUNNING` и `attempts+1` коммитятся перед вызовом обработчика. Задача, найденная в `RUNNING` при возобновлении, — прерванная попытка, её перезапускают.
3. **Успех и checkpoint — в одной транзакции** (`tasks.status=SUCCEEDED` + `checkpoints`). Подтверждённое не теряется и не выполняется повторно.
4. **Журнал эффектов (`effects`).** Побочный эффект (коммит, push, создание PR) выполняется через `ctx.effect(key, action, probe)`:
   - `applied` — вернуть сохранённый результат;
   - `intent` без `applied` (упали посередине) — вызвать `probe`, который проверяет фактическое состояние мира (например, коммит с трейлером `AI-Coding-Task: <run>/<task>`); если эффект виден, отметить его применённым, иначе повторить;
   - иначе записать `intent`, выполнить, записать `applied`.
   Каждая запись журнала — отдельная зафиксированная транзакция.
5. **Отмена — кооперативная.** `run cancel` ставит `cancel_requested`. Если живого worker'а нет, run отменяется сразу; иначе worker видит флаг, отменяет выполняющиеся asyncio-задачи и переводит run в `CANCELLED`.

## Проверка
`tests/integration/test_recovery.py` запускает настоящий процесс-worker, который вызывает `os._exit(137)` после коммита (до записи `applied`) и до коммита. Второй worker возобновляет run; тест проверяет ровно один коммит с трейлером, `attempts == 2` и что `main` не тронут. Контрольная проверка: если отключить `probe`, тест падает.

## Последствия
- Обработчики с побочными эффектами **обязаны** использовать `ctx.effect` и предоставлять `probe`, если эффект наблюдаем извне.
- Синхронный код обработчика, запущенный в потоке, нельзя прервать принудительно. Отмена и таймаут для него только кооперативные, а настоящая изоляция и kill — задача исполнителей S3 (subprocess/Docker).

## Альтернативы
- Advisory-блокировки БД — отклонено: в SQLite их нет, а сессионная блокировка в PostgreSQL исчезает вместе с соединением, но не защищает от «зомби» с живым соединением.
- Двухфазный коммит с git — невозможен.
- Идемпотентность только по содержимому коммита — ненадёжна, если между попытками изменились другие файлы.
