# ADR-0040: AI Changes Review — проверка изменений по фрагментам

- Статус: Принято
- Дата: 2026-11-06
- Уточняет: [ADR-0036](0036-workspaces-and-browser-terminal.md), [ADR-0039](0039-nexus-web-ui.md)

## Контекст

Агент чата (Claude Code, Codex) меняет файлы рабочей области. До этого решения пользователь видел только список изменённых файлов (`git status`) и мог зафиксировать всё сразу.

Требования интерфейса (Code Studio, ТЗ §5 о согласии человека):
- видеть сами изменения, построчно и бок о бок;
- принимать или отклонять их по отдельным фрагментам;
- фиксировать только принятое.

Git рабочей области выполняется только в контейнере пользователя (ADR-0036): сервер не запускает git в рабочих областях.

## Решение

1. **Два слоя изменений:**
   - **на проверке** — рабочее дерево против индекса (`git diff`) и неотслеживаемые файлы;
   - **принято** — индекс против HEAD (`git diff --cached`).

   Решение по фрагменту:

   | Действие | Команда в контейнере | Что меняется |
   |---|---|---|
   | Принять фрагмент или файл | `git apply --cached --recount` (патч на stdin) | Фрагмент индексируется |
   | Отклонить фрагмент или файл | `git apply -R --recount` | Фрагмент откатывается в файле |
   | Вернуть на проверку | `git apply --cached -R --recount` | Фрагмент убирается из индекса |
   | Принять новый файл | `git add -- <путь>` | Файл индексируется |
   | Удалить новый файл | `git clean --force -- <путь>` | Удаляется только неотслеживаемый файл |
   | Зафиксировать принятое | `git commit` без `add` | Коммит только индекса |

2. **Дифф только читает:** `git -c core.quotepath=off diff --no-color --no-ext-diff --no-textconv -M`. Внешние diff-программы и фильтры из конфигурации репозитория не запускаются. Новые файлы выдаются как diff против `/dev/null`, не больше 200 файлов. Объём одного слоя — до 4 МБ, при превышении интерфейс говорит, что показана часть.

3. **API:**
   - `GET /projects/{id}/workspace/diff` отдаёт файлы и фрагменты (номера строк, строки, патч каждого фрагмента).
   - `POST /projects/{id}/workspace/review` принимает `{action, patch | path}`.
   - `POST …/workspace/commit` принимает `staged_only`.
   - Право — `workspace.use`, как у остальных git-операций.
   - Браузер отправляет назад патч фрагмента из того же диффа. Сервер проверяет, что это один файл, есть хотя бы один фрагмент и размер не больше 1 МБ, а путь новых файлов — относительный, без `..` и `.git`. `git apply` сам отказывается от путей вне репозитория.
   - Если фрагмент больше не накладывается (файл изменился после показа диффа), ответ 409, и интерфейс перечитывает список.
   - Каждое решение пишется в журнал (`workspace.review`): действие и путь, без содержимого.

4. **Интерфейс** (`web/src/review/ChangesReview.tsx`):
   - вкладка Diff в AI Workspace со счётчиком того, что ждёт решения;
   - «Изменения» в Code Studio;
   - построчный вид и вид «Рядом» (на экранах уже 720 px — всегда построчный);
   - действия по фрагменту, по файлу и «Принять всё»;
   - «Зафиксировать принятое».

   После каждого хода агента список обновляется. Отклонение перечитывает дерево и открытый файл.

## Последствия

- Пользователь согласует изменения агента по фрагментам до коммита. Коммит содержит только принятое, а непроверенное остаётся на проверке.
- Двоичные файлы построчно не показываются и фрагментами не принимаются.
- Inline-подсказки ИИ прямо в редакторе по-прежнему нет: решение касается проверки уже сделанных изменений.

## Альтернативы

- **Git на сервере по каталогу рабочей области.** Отклонено: противоречит ADR-0036, так как репозиторий принадлежит пользователю (хуки, конфигурация).
- **Принятие на клиенте с перезаписью файла целиком.** Отклонено: затёрло бы изменения агента, сделанные во время проверки. `git apply` с проверкой контекста отказывает, если файл изменился.
