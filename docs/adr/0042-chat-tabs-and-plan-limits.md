# ADR-0042: Вкладки чатов, удаление чата и лимиты подписок

- Статус: Принято
- Дата: 2026-11-06
- Уточняет: [ADR-0037](0037-ai-chat-agents.md)

## Контекст

В панели чата был открыт один чат: другой выбирался из списка, и предыдущий пропадал из вида, хотя его агент продолжал работать. Удалить чат было нельзя.

Пользователи работают по подпискам Claude (Pro/Max) и ChatGPT (Plus/Pro), а у них есть лимиты: окно 5 часов и неделя. Узнать, сколько израсходовано и когда сброс, можно было только командой в терминале.

Что отдают CLI (проверено 2026-11-06 на версиях образа):

- **Claude Code 2.1.309.** Локальная команда `/usage` работает в неинтерактивном режиме (`supportsNonInteractive`). Запуск `claude -p --output-format stream-json --verbose --no-session-persistence --strict-mcp-config /usage`:
  - модель не вызывает и сессию не сохраняет;
  - отвечает за секунды;
  - кроме текста, присылает структурированный `usage_report.rate_limits.limits[]`: `kind` (`session`, `weekly_all`, `weekly_scoped`), `group`, `percent`, `resets_at` (ISO 8601), `scope` (модель окна), `severity`.

  Отчёт есть только у подписок claude.ai. При входе через Console или по API-ключу лимитов подписки нет, остаётся текст.
  Во время хода Claude Code присылает `rate_limit_event`, когда расход окна меняется.
- **Codex 0.163.0.** `account/rateLimits/read` в `codex app-server` возвращает `rateLimits.primary` и `secondary`: `usedPercent`, `windowDurationMins` (300 или 10080), `resetsAt` (Unix-секунды), `planType`. После хода приходит уведомление `account/rateLimits/updated`.

## Решение

1. **Несколько чатов во вкладках.**
   - Служба `ai-coding-agent` передаёт клиенту события всех чатов, которые он открыл (`open`), пока он не закроет их операцией `close`. Раньше клиент следил только за последним открытым чатом.
   - Новый чат — вкладка-черновик. Операция `new` несёт `ref` вкладки, а `opened` возвращает его, чтобы панель знала, какой черновик стал чатом.
   - Вкладка в фоне показывает, что агент работает или ждёт ответа на запрос разрешения. У каждой вкладки своё поле ввода.
   - Закрыть вкладку — не остановить агента: чат остаётся во «Всех чатах».
   - Открытые вкладки проекта запоминаются в браузере (`localStorage`). Вкладок не больше восьми, сверх этого закрывается самая старая неактивная.
2. **Удаление чата** — операция `delete`.
   - Пока агент работает, служба удаление отклоняет: сначала «Остановить».
   - Служба останавливает процесс агента, удаляет запись и журнал чата (`~/.ai-coding/chats/<project>/<id>.json(l)`) и сообщает всем клиентам событие `deleted`.
   - Собственная история CLI (`~/.claude/projects`, `~/.codex/sessions`) остаётся, как при удалении чата в их интерфейсах.
   - В панели удаление подтверждается вторым нажатием.
3. **Лимиты подписок** — операция `usage` {agent, refresh}.
   - Служба читает лимиты официальными средствами CLI: `/usage` у Claude Code, `account/rateLimits/read` у Codex. Учётные данные она по-прежнему не читает.
   - Лимиты приводятся к общему виду: окно (`session` — 5 часов, `week`), модель окна, процент, время сброса.
   - Прочитанное хранится в памяти 5 минут или до сброса окна и читается не чаще раза в 30 секунд. Чтение заново запускают «Обновить», конец хода и `rate_limit_event` у Claude Code. Уведомление `account/rateLimits/updated` у Codex применяется сразу.
   - Claude Code для `/usage` запускается в домашней папке, а не в проекте. Так настройки и hooks репозитория при этом не выполняются.
   - В шапке панели — значок «5 ч 4% · нед. 58%» для агента вкладки. По нажатию — по каждому агенту, в который выполнен вход, проценты, «осталось» и «сброс через 3 ч 55 мин (23:19)».
4. **Совместимость.** `hello` сообщает `features` (`tabs`, `delete`, `usage`).
   - Со службой из старого образа панель открывает чат заново при переключении вкладки и не показывает удаление и лимиты, пока среду не перезапустят.
   - Из браузера к службе проходят операции `hello`, `new`, `open`, `close`, `delete`, `send`, `approve`, `interrupt`, `login`, `usage`.

## Последствия

- Несколько задач идут параллельно и видны сразу. Вопрос агента в фоновой вкладке не теряется.
- Перед долгой задачей видно, хватит ли лимита и когда он восстановится.
- Чтобы получить вкладки в фоне, удаление и лимиты, нужен новый образ рабочей области (`ai-coding-agent` входит в него) и «Перезапустить среду».
- Формат `usage_report` и `rate_limits` — протокол CLI, он может измениться. Версии CLI закреплены в образе, разбор проверяется в `tests/integration/test_workspace_agent.py` фейковыми CLI с ответами этих версий. Если отчёта нет, панель показывает текст CLI.

## Альтернативы

| Вариант | Почему нет |
| --- | --- |
| Читать OAuth-токен из `~/.claude` и запрашивать лимиты у API Anthropic напрямую | Нарушает принцип ADR-0037: платформа не читает учётные данные пользователя. Это неофициальный путь. |
| Отправлять `/usage` в процесс открытого чата | Команда попадает в переписку чата и занимает его ход. Без открытого чата Claude Code лимитов не узнать. |
| Отдельное WebSocket-соединение на каждую вкладку | По `docker exec` на вкладку и отдельная повторная авторизация. Одно соединение с подпиской на несколько чатов проще и дешевле. |
| Считать лимиты по событиям хода (`rate_limit_event`) без `/usage` | Событие описывает только текущее ограничивающее окно и приходит лишь во время работы. До первого хода лимитов не было бы видно. |
