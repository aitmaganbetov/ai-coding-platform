# ADR-0043: GitHub Actions со стороны сервера

- Статус: Принято
- Дата: 2026-11-06
- Уточняет: [ADR-0039](0039-nexus-web-ui.md) (страница «Инфраструктура», вкладка проекта «Интеграции»); используется в [ADR-0048](0048-deploy-adapter.md)

## Контекст

Интеграция с GitHub (`ai_coding.integrations.github`) была у CLI и workflow pull request. Сервер GitHub Actions не опрашивал: на странице «Инфраструктура» было написано «не подключено, сервер их не опрашивает». Пользователь просил, чтобы GitHub Actions можно было включить и настроить в вебе и видеть их состояние там же.

## Решение

1. **Подключение — у каждого проекта своё.**
   - Раздел настроек `github`: `enabled` (по умолчанию выключено), `repository` (`owner/name`; принимается и URL репозитория), `api_url` (GitHub или GitHub Enterprise Server, только https и публичный адрес), `default_ref`.
   - Токен — секрет проекта `github.token`: fine-grained token на репозиторий (Actions — чтение и запись, Contents — чтение). Хранится зашифрованным и никогда не возвращается: для тех, кто управляет проектом, показываются только последние символы.
   - Менять подключение может `project.settings` (владелец, мейнтейнер). Читать могут все участники.

2. **Выключено — значит, GitHub не трогается.** Пока `enabled` ложно, запуски, workflow, задания и dispatch отвечают 409 «GitHub Actions are turned off…», а деплой через GitHub Actions не запускается. Исключение — явная «Проверка подключения»: её можно сделать до включения.

3. **Эндпоинты.** Доступ проверяется первым; ввод разбирается после проверки.
   - `GET /github/status` — сводка по всем проектам, которые видит вызывающий: сколько подключено, сколько включено, где последняя проверка или опрос закончились ошибкой;
   - `GET|PUT /projects/{id}/github` — раздел и признак токена; `version` из прочитанного не даёт перезаписать чужое изменение;
   - `GET /projects/{id}/github/check` — `ok` с репозиторием, приватностью, веткой по умолчанию и правами токена в репозитории, или `ok: false` с `reason` и текстом;
   - `GET /projects/{id}/github/workflows`, `GET …/runs?workflow=&branch=&limit=`, `GET …/runs/{gh_run_id}/jobs` — право `run.view`;
   - `POST /projects/{id}/github/workflows/{file}/dispatch` `{ref, inputs}` — право `run.create_changes`, событие журнала `github.dispatch` (имена входов без значений).

   Что делать с GitHub, решают права платформы, а не области токена.

4. **Ошибки понятны и без токена.** Ответ GitHub переводится в код `reason`, а веб объясняет его по-русски:

   | Ситуация | `reason` | HTTP |
   |---|---|---|
   | нет репозитория | `no_repository` | 409 |
   | нет токена | `no_token` | 409 |
   | интеграция выключена | `disabled` | 409 |
   | токен отклонён (401) | `bad_token` | 502 |
   | токену не хватает прав (403) | `forbidden` | 502 |
   | репозиторий или workflow не найден (404) | `not_found` | 502 |
   | лимит запросов | `rate_limited` | 502 |
   | GitHub недоступен | `unreachable` | 502 |

   Клиент вычищает токен из сообщений. Таймаут — 15 с, один повтор, ожидание лимита — не дольше 5 с.

5. **Последний вызов запоминается.** Итог последнего вызова GitHub (проверка или опрос: успех или `reason`) сервер сам пишет в раздел `github_status`. По нему «Инфраструктура» показывает проблемные проекты.

6. **Только публичные адреса.** Синхронный транспорт `PublicOnlySyncTransport` проверяет при каждом запросе, что все адреса хоста публичные, и соединяется с проверенным адресом. Иначе адрес API, заданный мейнтейнером, позволил бы прощупывать внутреннюю сеть через сообщения об ошибках. Поэтому GitHub Enterprise Server должен быть доступен по публичному адресу.

7. **Веб:**
   - вкладка проекта «Интеграции» (`#/projects/<id>?tab=integrations`): переключатель «Включить GitHub Actions», репозиторий, ветка по умолчанию, адрес API, токен (`SecretField`) и «Проверить подключение» с результатом на месте;
   - «Инфраструктура»: плитка GitHub Actions — подключено X из Y проектов, включено Z, ошибки. Панель показывает каждый проект с состоянием, ошибкой и ссылкой «Настроить». Для текущего проекта — последние запуски с заданиями по запросу и запуск workflow для разработчиков и выше.

## Последствия

- Сервер опрашивает GitHub только по запросу открытой страницы, раз в 15–60 с. Фонового опроса нет.
- Права токена в репозитории видны в проверке. Слишком широкий токен заметен, но не запрещён.
- GitHub App вместо токена (установка на организацию) не сделан: клиент его поддерживает, а веб пока нет.
