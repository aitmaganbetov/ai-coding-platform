# ADR-0006: Оркестратор — явный FSM, DAG задач, журнал событий и checkpoints

- Статус: Принято; реализовано в S2 (`ai_coding.orchestrator`), детали восстановления — ADR-0016.
- Дата: 2026-11-05

## Контекст
ТЗ §4–§5: состояния `CREATED → DISCOVERY → PLANNED → AWAITING_APPROVAL → RUNNING → VERIFYING → COMPLETED` + `FAILED, CANCELLED, PAUSED`; переходы идемпотентны и журналируются; после рестарта выполнение продолжается с последнего подтверждённого checkpoint **без повторного применения изменений** (AC-04). Нужны последовательные и параллельные шаги, DAG-зависимости, ограничения ресурсов, retry с backoff, отмена и тайм-аут (FR-08, FR-09).

## Решение
Компоненты Orchestrator Engine (`ai_coding.orchestrator`):

| Компонент | Ответственность |
| --- | --- |
| Task Planner | Строит DAG шагов с зависимостями, критериями успеха и бюджетом; проверка ацикличности |
| Agent Registry | Каталог агентов (встроенные + entry points), их capabilities, стоимость, разрешённые инструменты |
| Agent Router | Выбор агента по capability, правам, стоимости и доступности |
| Workflow Executor | Топологическое исполнение DAG, пул с лимитом `max_parallel_tasks`, семафоры ресурсов |
| Context Manager | Индекс репозитория, минимальный релевантный контекст, исключение секретов (FR-18) |
| State Manager | FSM переходов; таблица допустимых переходов — единственный источник истины |
| Checkpoint Manager | Атомарная фиксация checkpoint после подтверждённого шага |
| Policy Engine | Policy-as-code: allowlist команд, egress, пути записи, бюджет |
| Approval Manager | Human-in-the-loop: запросы, сроки, роли подтверждающих |
| Result Aggregator | Единый итог; статус теста берётся только из реального результата инструмента |
| Audit Logger | Append-only события с actor/project_id/run_id/timestamp/outcome |
| Retry & Recovery | Экспоненциальный backoff с jitter, классификация ошибок (transient/permanent), возобновление |

Инварианты:
- **Переход** = запись события `(run_id, seq, from, to, idempotency_key)` + обновление `state/version` в одной транзакции. Повтор того же события с тем же ключом — no-op.
- **Побочные эффекты** (коммит, push, PR) выполняются только через *идемпотентные эффекты*: ключ эффекта (например, `run_id/task_id/commit`) сохраняется до выполнения; при восстановлении эффект проверяется по фактическому состоянию (есть ли коммит с trailer `AI-Coding-Task: <task_id>`) и не повторяется.
- Checkpoint фиксируется только после верификации шага (VERIFYING → COMPLETED шага).
- Критические переходы покрываются тестами на 100% ветвей (NFR-06).

## Последствия
Восстановление после `kill -9` worker'а детерминировано. Таблица переходов легко ревьюится и визуализируется.

## Альтернативы
Temporal/Prefect/Celery canvas — отклонено: тяжёлая инфраструктура для Local Lite и offline-режима (ТЗ §15: offline через локальный scheduler). LangGraph — отклонено как ядро: AI-специфичен, а оркестратор должен работать без LLM.
