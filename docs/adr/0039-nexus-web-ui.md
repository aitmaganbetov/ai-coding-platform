# ADR-0039: Web UI «NEXUS Developer OS»

- Статус: Принято
- Дата: 2026-11-06
- Уточняет: [ADR-0036](0036-workspaces-and-browser-terminal.md), [ADR-0037](0037-ai-chat-agents.md), [ADR-0038](0038-orchestrator-tools-for-chat-agents.md)

## Контекст

Web UI вырос из нескольких независимых страниц: проекты, run, рабочая область с чатом, пользователи, профиль. У них не было общей навигации, сводных экранов, единой дизайн-системы и тем.

Нужен единый интерфейс управления всем жизненным циклом:
- обзор (Mission Control);
- AI Workspace с режимами работы;
- задачи и согласования;
- агенты;
- Code Studio;
- Audit Center;
- Quality Gates;
- модели;
- инфраструктура;
- настройки.

Ограничения:
- строгая CSP (`script-src 'self'`);
- данные только реальные, без вымышленных статусов;
- существующие функции не теряются;
- интерфейс адаптивен от 320 до 1920 px.

## Решение

1. **Дизайн-токены** (`web/src/theme.css`). Все цвета, размеры, радиусы, тени и анимации задаются CSS-переменными. Темы:
   - Obsidian Dark — основная;
   - Arctic Light;
   - Midnight OLED;
   - «как в системе» (`prefers-color-scheme`).

   Акцентный цвет пользователь может выбрать свой. Цвета используются по смыслу (успех, предупреждение, ошибка, активная задача). При `prefers-reduced-motion` анимации отключаются. Старые переменные (`--bg`, `--card`, `--accent`…) стали алиасами, поэтому страницы, написанные до NEXUS, получают темы без переписывания.

2. **Дизайн-система** (`web/src/ui/`). Компоненты:
   - кнопки и ссылки-кнопки;
   - бейджи состояний run'а, severity и Quality Gates;
   - карточки bento и показатели;
   - вкладки с клавиатурной навигацией;
   - сегментный переключатель, поиск, выпадающий список;
   - таблица с сортировкой;
   - пустое, ошибочное и загрузочное состояния, а также `QueryState`, который выбирает между ними;
   - блок кода с копированием;
   - диалоги, меню, подсказки, уведомления.

   Диалоги, меню и подсказки построены на Radix UI ради доступности: фокус, клавиатура, ARIA.

3. **App Shell** (`web/src/shell/`) из четырёх зон:
   - **Sidebar**: переключатель проекта, избранное, группы разделов, сворачивание до иконок.
   - **Командная строка**: хлебные крошки, поиск, статус сервера (`/readyz`), ИИ-провайдер проекта, активные задачи, согласования, тема, профиль.
   - **Рабочая область** по центру.
   - **AI Copilot** справа: настоящий чат рабочей области текущего проекта (ADR-0037).

   `Ctrl/Cmd+K` открывает командную палитру: разделы, проекты, действия, последние задачи. Маршрутизация через hash, старые адреса продолжают работать. Настройки интерфейса (тема, акцент, избранное, текущий проект) хранятся в `localStorage` (zustand) и не мешают работе, если хранилище недоступно.

4. **Данные.** TanStack Query кэширует ответы API. Активные run'ы опрашиваются, завершённые нет. При выходе пользователя кэш очищается.

   Для сводных экранов добавлены только читающие эндпоинты, с теми же правами, что и у существующих:
   - `GET /runs` и `GET /findings` по всем доступным проектам;
   - `GET /agents`;
   - `GET /projects/{id}/agent-executions` и `/usage`;
   - `GET /system` (только администраторы);
   - `config` в `GET /projects/{id}` и `dependencies`/`gates`/`usage` в `GET /runs/{id}`.

   Администратор без членства в проекте не видит его данных, как и раньше.

5. **Честность данных.** Разделы, для которых у платформы нет источника, показывают «не подключено» и объясняют почему. Вымышленных статусов нет:
   - деплой (вне рамок v2.1);
   - GitHub Actions на стороне сервера;
   - детализация отдельных тестов (JUnit).

6. **Стек и отступления от рекомендованного:**
   - Сохранены React 18, TypeScript и Vite. Добавлены lucide-react, TanStack Query, zustand, Radix UI, Recharts (только в ленивых чанках Mission Control и «Моделей»), React Flow (только в чанке графа run'а) и шрифты Inter / JetBrains Mono через `@fontsource`. Версии закреплены точно и опубликованы не позже чем за две недели до установки.
   - **CodeMirror 6 вместо Monaco.** CodeMirror уже встроен, работает со строгой CSP без web workers из blob, и он в несколько раз легче.
   - **CSS-переменные и собственные компонентные стили вместо Tailwind и shadcn/ui.** Требование ТЗ к токенам выполнено напрямую, Radix даёт ту же доступность, что и shadcn, а перевода всей разметки на утилитарные классы не нужно.
   - Тяжёлые разделы и страницы загружаются лениво. Основной чанк — около 117 КБ gzip.

## Последствия

- Единая навигация и сводные экраны на реальных данных, три темы и адаптивность от 320 px.
- Проверки:
  - компонентные тесты (`npx vitest run`);
  - сквозная проверка `web/e2e/nexus.mjs`: каждый раздел на ширинах 320–1920 px без горизонтального переполнения и без ошибок в консоли (включая нарушения CSP), командная палитра, смена темы.
- Новые разделы добавляются на тех же токенах и компонентах. Источник данных — только API.
- Monaco и Tailwind можно подключить позже отдельным решением, если понадобятся (например, inline-подсказки ИИ в редакторе).

## Альтернативы

- **Tailwind и shadcn/ui.** Отклонено на этом этапе. Пришлось бы переписать всю разметку, а токены, доступность и единообразие и так обеспечены.
- **Monaco Editor.** Отклонено. Он требует web workers (усложняет CSP) и заметно увеличивает загрузку, а для просмотра и правки достаточно CodeMirror.
- **Демонстрационные данные для отсутствующих разделов.** Отклонено. ТЗ и требования к интерфейсу запрещают выдавать вымышленные статусы за реальные.
