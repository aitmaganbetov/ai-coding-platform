# ADR-0023: LLM-адаптеры на httpx, маршрутизация с fallback, кэш ответов

- Статус: Принято (уточняет ADR-0009)
- Дата: 2026-11-05
- Спринт: S5 (B-410…B-414)

## Контекст
ADR-0009 зафиксировал порт `LLMProvider`, `GuardedLLM`, бюджеты и учёт `model_usage` (S2). Там же планировались адаптеры на официальных SDK. ТЗ требует:
- OpenAI, Anthropic, Ollama и vLLM (§4);
- работу офлайн на локальной модели (FR-12, AC-05);
- маршрутизацию и fallback (FR-15);
- маскировку секретов (FR-18);
- контроль стоимости (§18).

## Решение
1. **Адаптеры на httpx, без SDK провайдеров** (`llm/providers.py`). Изменение по сравнению с ADR-0009. Причины:
   - один HTTP-стек для всех провайдеров: одинаковые таймауты, классификация ошибок и redaction;
   - проверку egress и тестирование без сети (`httpx.MockTransport`, fake-сервер на localhost) не нужно делать отдельно для каждого SDK;
   - меньше поверхность зависимостей — тот же довод, по которому в ADR-0009 отклонён LiteLLM.
2. **Протоколы.**
   - OpenAI — Chat Completions (`max_completion_tokens`, `response_format: json_schema`).
   - Ollama и vLLM — тот же формат через OpenAI-совместимый endpoint (`/v1`).
   - Anthropic — Messages API: `anthropic-version: 2023-06-01`, структурированный вывод через **принудительный вызов инструмента** `submit_result`, у которого `input_schema` = схема агента.
   - Ответ провайдера никогда не считается валидным сам по себе: его заново проверяет `GuardedLLM` по JSON Schema.
3. **Безопасность.**
   - Внешние провайдеры работают только по https; http допускается для loopback и для self-hosted Ollama/vLLM.
   - Ключи читаются из окружения по имени (`api_key_env`) и регистрируются в redactor.
   - Тексты ошибок провайдера проходят redaction и обрезаются.
4. **Классификация ошибок.**
   - Временные (`ProviderUnavailableError`): сеть, таймаут, 408/409/429, 5xx; учитывается `retry-after`.
   - Постоянные (`ProviderRequestError`): аутентификация, 4xx, отказ модели.
   - Обрезанный ответ (`finish_reason=length` / `stop_reason=max_tokens`) считается ошибкой: неполный JSON принимать нельзя.
5. **Маршрутизация** (`llm/router.py`, `agents/llm_factory.py`).
   - Цепочка: `ai.routing[agent]` или модель по умолчанию, затем `ai.fallback` без дублей.
   - Каждый маршрут идёт через свой `GuardedLLM`, поэтому политика, бюджет, redaction и проверка схемы применяются к каждой модели цепочки.
   - На следующий маршрут переходят при недоступности, отказе, невалидном ответе или запрете политикой (например, внешний провайдер при `local-only`).
   - Цепочка останавливается при необходимости approval `external_llm` (прогон ставится на паузу) и при исчерпании бюджета.
   - Если все маршруты упали и все сбои временные, это временная ошибка: оркестратор повторит шаг. Иначе ошибка постоянная.
   - Маршрут без ключа в окружении пропускается и показывается в `ai-coding agents list`.
6. **Approval внешнего провайдера.** Шаг агента сам проверяет `external_llm` для первой модели цепочки. Если нужен approval, прогон уходит в AWAITING_APPROVAL, а не переключается молча на fallback. До одобрения ни один байт не уходит наружу.
7. **Стоимость.** `ai.pricing` задаёт цену модели в USD за 1 млн токенов. Модели без цены ограничиваются бюджетом токенов. Предварительная оценка запроса проверяется до отправки.
8. **Кэш ответов** (`llm/cache.py`, `ai.cache`, по умолчанию включён).
   - Кэшируются только запросы с `temperature == 0`.
   - Ключ — SHA-256 от провайдера, endpoint, модели, всех сообщений **после redaction**, схемы и лимитов.
   - В кэш попадают только ответы, прошедшие проверку схемы. При попадании ответ проверяется снова, а бюджет и `model_usage` не тратятся.
   - Хранилище — `.ai-coding/cache/llm` проекта (каталог исключён из git); запись атомарная; повреждённая запись считается промахом.

## Последствия
- **Плюс:** офлайн-режим работает так же, как с внешним провайдером: та же политика, те же проверки.
- **Плюс:** новый OpenAI-совместимый сервер подключается одной строкой в конфигурации.
- **Минус:** изменения в API провайдеров отслеживаем сами, без обновлений SDK. Формы запросов и ответов покрыты тестами по документации.
- **Риск:** на реальных провайдерах адаптеры в этой среде не проверялись — нет ключей и нет доступа к загрузке моделей. План проверки — в отчёте S5.
