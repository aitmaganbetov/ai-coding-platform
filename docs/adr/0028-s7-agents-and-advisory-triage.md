# ADR-0028: Агенты Security, QA, Performance, DevOps, Maintenance; рекомендательный triage

- Статус: Принято
- Дата: 2026-11-05
- Спринт: S7 (B-604 … B-608, B-609, B-611)

## Контекст
ТЗ §6 определяет 12 агентов. В S5–S6 реализованы 7. ТЗ §10: AI не заменяет детерминированные проверки. ТЗ §12: README, issues, diff, зависимости и тестовые данные — недоверенные, это возможные prompt injection.

## Решение
1. **Пять агентов на базе `LLMAgent`** (ADR-0024): JSON-схема выхода и семантические проверки с циклом исправления. Схема ограничивает форму ответа, проверки — содержание.

   | Агент | Проверки |
   | --- | --- |
   | Security | Каждая находка сканера оценена ровно один раз, ссылки только на известные id. Закоммиченный секрет нельзя отклонить как `false_positive` (это решает человек через baseline). Дополнительные риски — только в показанном коде и в пределах файла |
   | QA | Каждый критерий приёмки покрыт тест-кейсом. Тест-кейсы лежат в тестовых файлах и на безопасных путях. Пробелы покрытия — только в показанных файлах |
   | Performance | Каждое узкое место опирается на переданные метрики (числа не выдумываются) и имеет бенчмарк для воспроизведения. В командах нет секретов |
   | DevOps | Граф стадий без циклов и неизвестных зависимостей. В командах нет секретов (только ссылки на хранилище секретов CI). Развёртывание в production — только с manual approval. Указанные окружения существуют. План отката не пустой. Пути CI безопасны |
   | Maintenance | Каждый источник (issue, находка, зависимость) запланирован или отложен с причиной, ничего не теряется. Обновление — только до версии, которую сканер указал как исправленную. У каждой задачи есть регрессионный тест в тестовом файле. Не больше 15 файлов на задачу |

2. **`ai-coding agents run NAME -i inputs.json`** запускает любого агента как одношаговый оркестрированный прогон с теми же гарантиями: политика агента, approvals внешнего LLM, бюджет, redaction, сохранённый результат. Репозиторий не меняется.
3. **Triage в AUDIT (`--triage`)** — рекомендательный шаг `audit.triage`.
   - Работает в фазе execution: внешняя модель ставит run на паузу для approval. Mid-run approvals разрешены только в execution (FSM).
   - Вердикты добавляются к находкам в отчёте, но **не меняют гейты**.
   - Файлы с найденными секретами в модель не отправляются.
   - Сбой модели или неприемлемый ответ дают `triage: failed`, аудит остаётся действительным. Запрос approval и превышение бюджета никогда не поглощаются: run ставится на паузу (`audit --resume`).
4. **Prompt injection (AC-07)** проверяется исходя из того, что модель **выполняет** внедрённую инструкцию. Ограничения не зависят от модели:
   - правила путей: `.git/`, `.ai-coding/`, выход за пределы проекта;
   - approval для критичных файлов (CI, конфигурация, lock-файлы, миграции);
   - коммиты только в рабочую ветку, без merge;
   - тесты в песочнице без сети;
   - исключение секретных файлов и redaction;
   - разделители `<input>`, которые нельзя закрыть изнутри;
   - семантические проверки агентов.

   Набор тестов нашёл утечку: файлы-подсказки цикла реализации (их может назвать план агента) обходили исключения контекста. Это исправлено — подсказки проходят те же правила и redaction.

## Последствия
- **Плюс:** все 12 агентов ТЗ §6 реализованы. Их выход проверяем и не даёт агенту прав сверх политики.
- **Ограничение:** QA, Performance и DevOps пока не встроены в отдельные режимы, их запускают через `agents run`. В S8 их подключат API и UI.
