# ADR-0031: Развёртывание сервера, хранилище артефактов S3, Web UI, метрики, экспорт и retention

- Статус: Принято
- Дата: 2026-11-05
- Уточняет: [ADR-0014](0014-api-and-web-ui.md), [ADR-0005](0005-persistence.md)

## Контекст

Требования к Self-Hosted профилю (ТЗ §15):
- docker-compose;
- обязательный backup;
- TLS;
- ротация ключей;
- MinIO как хранилище артефактов (§4);
- Web UI на React (§4);
- метрики и логи без секретов (NFR-07);
- экспорт данных проекта и удаление по retention (NFR-08).

Сервер (ADR-0030) запускает песочницы через Docker: доступ к демону эквивалентен root на хосте.

## Решение

1. **Образ.**
   - Многоступенчатый `deploy/Dockerfile`: сборка UI (Node), сборка wheel, runtime на `python:slim`. Все базовые образы закреплены по digest.
   - Процесс работает от uid 10001. В runtime есть только `git` и клиент Docker; UI раздаётся из `/opt/ai-coding/ui`.
   - `ENTRYPOINT ai-coding server`: один образ для `serve`, `worker`, `migrate`, `user`, `token`.

2. **docker-compose.**
   - Сервисы: `postgres`, `api`, `worker`, `caddy`.
   - Все серверные контейнеры: `read_only`, `cap_drop: ALL`, `no-new-privileges`.
   - **У API нет доступа к Docker.** Docker-сокет есть только у worker'а: он запускает песочницы, которые сокет не получают (ADR-0018).
   - Каталог данных смонтирован по одинаковому пути внутри и снаружи: worker передаёт демону пути хоста для монтирования в песочницы.
   - TLS терминирует Caddy с автоматическими сертификатами; API доверяет `X-Forwarded-*` только от него.
   - Секреты — только в `deploy/.env`, он вне git; есть шаблон `.env.example`.

3. **Backup и ротация.**
   - `deploy/backup.sh`: `pg_dump` в gzip, `umask 077`, атомарное переименование, удаление копий старше N дней. Запуск — из cron.
   - Ротация токенов — через API (новый токен, старый отзывается сразу). Остальные секреты меняются через окружение и перезапуск, процедуры описаны в [server.md](../server.md).
   - Секретов в коде и в БД нет: в БД хранятся только хэши паролей и токенов.

4. **Хранилище артефактов S3/MinIO (B-705).**
   - Протокол `ArtifactStore` (`put/get/exists/delete/clear`) с реализациями `LocalArtifactStore` и `S3ArtifactStore`.
   - Выбор: `artifacts.store: minio` в конфигурации проекта; параметры подключения — из окружения `AI_CODING_S3_*`, не из конфигурации проекта.
   - Ключи адресуются по содержимому (`projects/<имя>/<sha256>`). При чтении содержимое сверяется с хэшем, так что подмена объекта в bucket'е обнаруживается.
   - Подпись AWS SigV4 реализована на `httpx` без boto3 (меньше зависимостей).

5. **Web UI (B-706).**
   - React 18 + TypeScript + Vite в `web/`; сборка — статика, которую раздаёт API.
   - Экраны: вход, проекты, проект (запуск прогона, прогоны, находки, участники, журнал, экспорт), прогон (задачи, approve/reject, отмена, артефакты, опрос каждые 2 с).
   - Токен хранится в `sessionStorage` и отправляется заголовком `Authorization`. Cookie нет, поэтому CSRF неприменим. `credentials: "omit"`.
   - CSP `default-src 'self'` без inline-скриптов: в CI отдельная проверка, что в собранном `index.html` нет inline `<script>`.
   - Кнопки скрываются по роли только для удобства. Права проверяет сервер, и тесты API это подтверждают.
   - Клиент типизирован вручную, отклонение от ADR-0014 обосновано в ADR-0030.

6. **Метрики (B-707).**
   - `/metrics` в текстовом формате Prometheus сформирован вручную, без клиентской библиотеки.
   - Метрики: счётчики и гистограмма HTTP по шаблону маршрута (не по фактическому пути — иначе идентификаторы раздули бы кардинальность), состояния прогонов и заданий из БД, активные прогоны процесса worker'а.
   - Доступ: отдельный `METRICS_TOKEN` или администратор.
   - Логи: JSON в stderr с `run_id` и redaction (ADR-0017). OpenTelemetry не подключён: трассировка — опция ТЗ, а `run_id` в логах и журнале уже связывает события прогона.

7. **Экспорт и retention (B-709).**
   - Экспорт (owner) — ZIP: JSON всех таблиц проекта и файлы артефактов. Данные других проектов не попадают, это проверяет AC-08.
   - Удаление проекта (owner): каскад в БД, `store.clear()`, удаление клона, только если сервер сам его создал. При активных прогонах — `409`. Журнал аудита сохраняется: это доказательство, а не данные проекта.
   - Retention удаляет:
     - завершённые прогоны старше срока (`AI_CODING_SERVER_RETENTION_DAYS` или `artifacts.retention_days` проекта);
     - их артефакты, если на них не ссылаются другие прогоны;
     - ключи идемпотентности старше суток;
     - токены, отозванные или истёкшие более 30 дней назад.

     Запуск — `server purge` или раз в час в worker'е.

## Последствия

- Компрометация API не даёт доступа к Docker. Компрометация worker'а даёт его, поэтому worker должен работать на выделенном хосте. Rootless Docker или удалённый демон — рекомендация для production (S9 hardening).
- Без MinIO-образа в среде разработки `S3ArtifactStore` проверен эталонным вектором подписи AWS и fake-сервером, который сам проверяет подпись. Прогон против настоящего MinIO — в плане S9.

## Альтернативы

- **boto3** — отклонено: большая зависимость ради шести запросов.
- **prometheus_client** — отклонено по той же причине. Формат простой, и тест его проверяет.
- **Cookie-сессии для UI** — отклонено: потребовались бы CSRF-защита и SameSite-настройки. Токен в `sessionStorage` не переживает закрытия вкладки.
- **Distroless runtime** — отклонено: worker'у нужны `git` и клиент Docker.
