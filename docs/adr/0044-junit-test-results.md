# ADR-0044: Результаты отдельных тестов (JUnit)

- Статус: Принято
- Дата: 2026-11-06
- Уточняет: [ADR-0039](0039-nexus-web-ui.md); gate тестов (ТЗ §10)

## Контекст

Gate тестов сообщал только итог прогона: «прошли», «упали N», «пропущены» и причину. Какие тесты упали, где, сколько длились, что сломалось по сравнению с прошлым прогоном — видно не было. Страница «Тесты и Quality Gates» честно писала, что API этого не отдаёт.

Тесты проекта выполняет платформа:

- в DEVELOP, MODERNIZE и MAINTAIN — в песочнице Docker (`SandboxTestRunner`: pytest, `node --test`, `npm test` или своя команда `quality_gates.tests.command`);
- в аудите — инструменты категории «тесты»: `go test -json` и `cargo test`.

Отчёт пишется кодом проекта внутри песочницы, поэтому он недоверенный: размер, сущности XML, ссылки на файлы хоста.

## Решение

1. **Общий формат — JUnit XML.** Его пишут сами раннеры, платформа только добавляет флаги:
   - pytest: `--junitxml=/deps/junit.xml -o junit_family=xunit1` (в xunit1 у теста есть `file` и `line`);
   - `node --test` (в `package.json` нет своего скрипта `test` или он ровно `node --test`): `--test-reporter=tap` в stdout (по нему считается итог, как раньше) и `--test-reporter=junit` в файл;
   - Vitest (скрипт `vitest` / `vitest run`): `--reporter=default --reporter=junit --outputFile.junit=…`, `CI=true`;
   - своя команда, которая пишет `/deps/junit.xml`, тоже даёт отчёт;
   - `go test -json` и вывод `cargo test` переводятся в ту же модель и сохраняются как JUnit (у cargo нет длительностей: стабильный libtest их не печатает).

   Не поддерживаются: Jest и mocha через `npm test` (нужен пакет-репортер, офлайн его не поставить: такой прогон честно говорит «команда не пишет JUnit»); PHPUnit (раннера тестов PHP в платформе нет); Playwright и k6 (не переводятся).

2. **Отчёт — артефакт прогона.**
   - DEVELOP, MODERNIZE, MAINTAIN: `junit-<шаг>.xml`. Шаг, который гоняет тесты несколько раз (итерации реализации), хранит последний отчёт.
   - Аудит: `junit-<инструмент>.xml`.
   - Тип `text/xml`: при сохранении секреты вычищаются, как в любом текстовом артефакте.
   - Файл песочницы читается без перехода по ссылкам (`O_NOFOLLOW`), только обычный файл, не больше 10 МБ. Каталог, канал или ссылка на файл хоста отчётом не считаются.

3. **Безопасный разбор.** Отчёт разбирает `expat`:
   - документ с `DOCTYPE` или объявлениями сущностей отвергается целиком (защита от billion laughs и XXE), внешние сущности не загружаются;
   - лимиты: 10 МБ и глубина 64;
   - вывод теста обрезается до ~4 КБ;
   - пути приводятся к путям проекта (песочница монтирует его в `/work`). Пути вне проекта — библиотеки, `node_modules`, `/deps`, `..` — отбрасываются;
   - упавший тест указывает на строку падения из текста ошибки;
   - номера строк pytest (с нуля) переводятся в обычные.

4. **API** (право `run.view`; доступ проверяется до разбора параметров, чужой получает 404):
   - `GET /runs/{id}/tests`. Ответ:
     - `totals` — `tests`, `passed`, `failed`, `errors`, `skipped`, `time`;
     - `suites` — наборы, в каждом `cases` с полями `name`, `classname`, `key`, `file`, `line`, `time`, `status`, `message`, `details`; упавшие идут первыми;
     - `reports` — имена отчётов; `primary` отмечает отчёты, вошедшие в итог;
     - `problems` — нечитаемые отчёты;
     - `compared_with`, `regressions` (прошли в прошлом прогоне с результатами, падают теперь), `fixed`;
     - если результатов нет — `reason` и `setting`: настройка, от которой это зависит, например `quality_gates.tests.enabled`, `execution.docker.network` или `quality_gates.tests.command`.

     В итог аудита входят отчёты всех инструментов. У остальных режимов в итог входит последний отчёт (тесты итогового изменения), прочие (например, базовая линия MODERNIZE) только перечислены.
   - `GET /projects/{id}/test-runs?limit=` — последние прогоны с тестами: итоги, упавшие тесты, регрессии, причины. Без наборов.
   - `GET /projects/{id}/tests/history?test=<classname::name>` — один тест по прогонам.

   Разобранные отчёты кэшируются по SHA-256: артефакт не меняется.

5. **Интерфейс.** На странице «Тесты и Quality Gates» есть раздел «Тестовые прогоны»:
   - список прогонов с полосой «пройдено / упало / пропущено» и числом регрессий;
   - у выбранного прогона: итоги, регрессии, наборы и тесты (по умолчанию только упавшие, есть поиск), сообщение и вывод теста, история теста по прогонам, самые медленные тесты;
   - ссылки «Открыть в Code Studio» на файл и строку;
   - прогон без отчёта объясняет причину и называет настройку.

## Последствия

- Видно, какой тест упал, где и с какого прогона. Из ошибки можно сразу перейти к строке в Code Studio.
- Новых таблиц и миграций нет: отчёты — обычные артефакты, их хранение и удаление (retention) общие. Отчёт, удалённый по сроку хранения, показывается как «больше не хранится».
- Регрессии считаются между соседними прогонами проекта с результатами, независимо от ветки и режима. Это подсказка, а не gate: решение по-прежнему принимает gate тестов.
- Проверки:
  - модульные тесты разбора (настоящие отчёты pytest, Vitest, `node --test`; DOCTYPE, XXE, размер, глубина, пути, go и cargo, обратная запись);
  - интеграционные тесты API (итоги, регрессии, причины, история, доступ);
  - прогон в настоящей песочнице (`node --test` пишет отчёт, упавший тест указывает на файл и строку);
  - компонентные тесты страницы.

## Альтернативы

- **defusedxml.** Его нет в образе сервера. `expat` с отказом от DOCTYPE и сущностей закрывает те же атаки без новой зависимости.
- **Таблица результатов тестов в БД.** Даёт быстрые выборки по истории, но требует миграции и дублирует артефакт. Пока прогонов десятки, хватает разбора с кэшем.
- **Разбор консольного вывода раннеров.** Хрупко и зависит от версии. JUnit — общий стабильный формат, а его разбор уже нужен для go и cargo.
