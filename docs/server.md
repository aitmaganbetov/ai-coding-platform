# Self-Hosted сервер: API, RBAC, worker'ы, Web UI

Многопользовательский режим платформы (ТЗ §3, §13, §15): REST API, роли в проектах, очередь прогонов в БД, worker'ы с Docker-песочницей и Web UI. Решения описаны в [ADR-0030](adr/0030-server-api-rbac-queue.md) и [ADR-0031](adr/0031-server-deployment-storage-ui.md).

```
Браузер / CLI / CI ──HTTPS──▶ Caddy (TLS) ──▶ api (FastAPI, Web UI) ──▶ PostgreSQL
                                                                         ▲
                                         worker ×N (≥10 прогонов каждый) ┘──▶ Docker-песочницы
```

API не запускает контейнеры. Worker забирает задания из очереди в БД и выполняет прогоны тем же оркестратором, что и CLI: FSM, checkpoints, approvals, аудит.

## Быстрый старт (docker-compose)

```bash
cp deploy/.env.example deploy/.env
```

Заполните в `deploy/.env` домен, длинный случайный `POSTGRES_PASSWORD` и каталог данных `AI_CODING_DATA`. Файл `.env` не коммитится.

```bash
sudo install -d -o 10001 -g 10001 -m 0750 /srv/ai-coding
```

```bash
export DOCKER_GID=$(getent group docker | cut -d: -f3)
```

```bash
docker compose -f deploy/docker-compose.yml up -d --build
```

```bash
docker compose -f deploy/docker-compose.yml run --rm api migrate
```

```bash
docker compose -f deploy/docker-compose.yml run --rm api user add admin --admin
```

Пароль запрашивается интерактивно (минимум 12 символов; `--password-stdin` для автоматизации). Затем откройте `https://<домен>/` и войдите. Дальше всё делается в Web UI (см. [Web UI](#web-ui)).

Образ: многоступенчатая сборка, все базовые образы закреплены по digest. Процесс работает от непривилегированного пользователя uid 10001. Контейнеры запускаются с `read_only`, `cap_drop: ALL` и `no-new-privileges`. Доступ к Docker есть только у worker'а; песочницы его не получают (ADR-0018).

## Web UI

Интерфейс «NEXUS Developer OS» ([ADR-0039](adr/0039-nexus-web-ui.md)).
- **Слева** — меню разделов: переключатель текущего проекта, избранное (звёздочка у раздела), сворачивание до иконок.
- **Сверху** — хлебные крошки, поиск и командная палитра (`Ctrl/Cmd+K`), статус сервера, ИИ-провайдер проекта, активные задачи, согласования, тема и профиль.
- **Справа** — AI Copilot: чат рабочей области текущего проекта.
- **Темы**: Obsidian Dark, Arctic Light, Midnight OLED или «как в системе», и свой акцентный цвет (меню палитры в верхней строке или «Настройки → Внешний вид»).

| Раздел | Кто видит | Что можно сделать |
| --- | --- | --- |
| **Mission Control** | все | Сводка по доступным проектам: задачи, согласования, безопасность, Quality Gates, качество кода, использование моделей, активность, состояние системы. «Новый проект», «Новая AI-задача», «Полный аудит» |
| **AI Workspace** | owner, maintainer, developer | Чат с Claude Code или Codex в режиме работы, вкладки «Код», «Изменения», «Тесты», «Логи», «Артефакты», ход работы агентов, терминал (см. ниже) |

Обзор проекта: сводка конфигурации, задачи, находки, участники и роли, журнал, «Интеграции» (GitHub Actions; владелец, мейнтейнер), экспорт, удаление (с подтверждением именем) |

Каталог агентов с тем, где каждый работает, и их состояние в проекте; карточка агента — все его задачи. Поток работы run'а |

| **Audit Center** | участники | Находки по категориям (качество, безопасность, зависимости…), фильтры, доказательства, «Исправить в чате», сравнение двух аудитов, «Полный аудит» |
| **Тесты и Gates** | участники | Quality Gates последних аудитов и их история; «Тестовые прогоны» — результаты отдельных тестов (см. ниже) |
| **Модели** | участники (менять — owner, maintainer) | ИИ-провайдер оркестратора: провайдер, модель, адрес, ключ (только запись), Private Mode, модели по агентам, бюджеты, «Проверить подключение» (см. ниже); использование и стоимость |
| **Инфраструктура** | все (подробности — администраторы) | Готовность сервера; очередь, worker'ы (в сети, состояние, хост); Local (CLI) — машины разработчиков; GitHub Actions проектов и запуски workflow; готовность баз уязвимостей и команда их подготовки |

### Проверка изменений (AI Changes Review)

Во вкладке **Diff** AI Workspace (число на вкладке — сколько ждёт решения) и в **«Изменениях»** Code Studio видны изменения вашей рабочей области ([ADR-0040](adr/0040-ai-changes-review.md)):
- **На проверке** — что изменили агент или вы. У каждого фрагмента есть «Принять» и «Отклонить». Отклонённый фрагмент откатывается в файле.
- **Новые файлы** — «Принять файл» или «Удалить».
- **Принято** — то, что войдёт в коммит. Любой фрагмент можно «Вернуть на проверку».
- **«Зафиксировать принятое»** коммитит только принятое, непроверенное остаётся на проверке.
- Виды «Построчно» и «Рядом». Если файл изменился после показа (например, агент ещё работает), фрагмент не применится, и список обновится.
- Двоичные файлы и изменения без построчных фрагментов (режим, имя) принимаются, откатываются и возвращаются целиком.

### ИИ в редакторе

([ADR-0041](adr/0041-ai-in-the-editor.md))
- Изменения агента подсвечены прямо в открытом файле. Над каждым — удалённые строки и кнопки «Принять» / «Отклонить». Пока в файле есть несохранённые правки, разметка скрыта.
- **Над выделенным кодом:** «Объяснить», «Исправить», «Улучшить», «Тесты», «Спросить…». `Ctrl+I` — «Спросить…» для выделения или текущей строки. Запрос уходит в чат рабочей области с путём, строками и кодом, ответ и изменения агента появляются в чате и в редакторе.
- Автодополнения «призрачным текстом» нет: каждый ответ Claude Code или Codex — это полный ход агента.

### Вкладки и Split View

([ADR-0045](adr/0045-split-view-and-workspace-tabs.md))
- **Вкладки.** В Code Studio и на вкладке Code в AI Workspace файлы открываются вкладками. Точка ● означает несохранённые правки. Такую вкладку можно закрыть только после подтверждения, средняя кнопка мыши тоже закрывает вкладку. Вкладки проекта запоминаются в этом браузере, причём только пути.
- **Две группы.** «Разделить редактор» добавляет справа вторую группу вкладок. «Открыть справа» и «Открыть слева» переносят вкладку в другую группу вместе с несохранёнными правками: файл открыт только в одной группе. Границу между группами можно тянуть. На узком экране группы переключаются.
- **Переход к строке.** Ссылка `#/projects/<id>/code?file=<путь>&line=<n>` открывает файл и подсвечивает строку.
- **Вкладки рабочих областей.** Над страницей — вкладки открытых рабочих областей, до восьми, недавние первыми.
- **Во весь экран.** Кнопка в шапке рабочей области скрывает меню, верхнюю строку и боковые панели. Esc возвращает их.

### Результаты отдельных тестов

([ADR-0044](adr/0044-junit-test-results.md)) Каждый запуск тестов оставляет отчёт JUnit как артефакт прогона `junit-*.xml`:

- тесты в песочнице (DEVELOP, MODERNIZE, MAINTAIN): pytest, `node --test`, Vitest или своя команда, если она пишет `/deps/junit.xml`;
- инструменты аудита `go test` и `cargo test`: их вывод переводится в JUnit.

Отчёт — недоверенные данные. Документы с DOCTYPE или сущностями отвергаются, лимиты — 10 МБ и глубина 64, пути приводятся к путям проекта. В итог аудита входят отчёты всех инструментов, в итог остальных режимов — последний отчёт. Если отчёта нет, API объясняет причину (`reason`) и называет настройку (`setting`). Доступ — `run.view`; он проверяется до разбора параметров.

### ИИ-провайдер из веба

([ADR-0046](adr/0046-ai-providers-from-web.md)) Провайдер, модель, адрес, маршруты агентов, бюджеты и Private Mode можно задать на странице «Модели». Эти значения действуют поверх `.ai-coding.yml` для запусков на сервере; незаданные поля берутся из файла. Ключ хранится как секрет проекта `ai.api_key` (нужен `AI_CODING_SERVER_SECRET_KEY`) и расшифровывается только при создании провайдера, в окружение процессов он не попадает. Private Mode включает `security.network: local-only`; при его выключении в allowlist добавляется только хост провайдера. Удалённый адрес — только https; адреса облачных метаданных сервер не вызывает. Переменные `AI_CODING_*` (секреты платформы и веб-ключи других проектов) конфигурация проекта не может назвать в `api_key_env`: такой проект получает 422 с объяснением.

### Деплой и GitHub Actions

([ADR-0043](adr/0043-github-actions.md), [ADR-0048](adr/0048-deploy-adapter.md)) Подключение к GitHub настраивается во вкладке проекта «Интеграции» (владелец, мейнтейнер): репозиторий, токен (fine-grained: Actions — чтение и запись, Contents — чтение) и переключатель «Включить GitHub Actions». Пока он выключен, сервер не обращается к GitHub для проекта. Адрес API — только https на публичный адрес. Для GitHub Enterprise Server внутренний адрес не подойдёт.

Среды деплоя задаются на странице «Деплой и среды». Деплой — run вида `deploy`. Production и среды «с подтверждением» ждут approve на странице run'а, до него ничего не запускается. Webhook получает JSON о деплое с заголовком `X-AI-Coding-Signature: sha256=<HMAC-SHA256 тела секретом среды>`: получатель обязан проверить подпись. Адреса webhook и проверки здоровья — только https на публичные хосты.

### Секреты проекта

Токен GitHub (`github.token`), ключ ИИ-провайдера (`ai.api_key`) и секреты webhook (`deploy.<среда>.webhook`) задаются в вебе и хранятся в БД зашифрованными: AES-256-GCM ключом `AI_CODING_SERVER_SECRET_KEY`, с привязкой к проекту и имени. Их можно только записать: API отдаёт последние символы, кто и когда задал, но не значение. Сервер расшифровывает секрет только для вызова того сервиса, для которого он задан. Без ключа сервера секреты не сохраняются, а интеграции, которым они нужны, объясняют это. Смена ключа — в разделе «Ротация ключей».

### Рабочая зона агентов

([ADR-0049](adr/0049-agent-workspace.md)) Раздел «Агенты» → «Рабочая зона» ставит задачу агентам оркестратора своими словами.
- **«Разработка»**: первая строка — заголовок, дальше подробности. Developer пишет код и тесты в песочнице, Reviewer проверяет (до 1–5 кругов), платформа прогоняет тесты проекта и коммитит результат в рабочую ветку `ai/…`; с подключённым GitHub — открывает pull request.
- **«Исправления»**: каждая строка — проблема («заголовок: подробности»). Maintenance составляет план, вы его утверждаете, Developer и Reviewer делают проверенное исправление.
- **Ход работы**: шаги с агентами, которые их выполняют, расход токенов, ошибки. Согласия (например, отправить код внешней модели, создать PR) — прямо здесь: «Разрешить» или «Отклонить».
- **Результат**: ветка, коммит, pull request, итог, план, изменённые файлы, замечания ревьюера и diff. «Доработать» ставит новую задачу от ветки результата.
- **Нужен ИИ-провайдер проекта** («Модели»). Рабочая зона показывает, чего не хватает. Агенты Requirements, Architect, Planner и Bootstrap работают только в CLI (`ai-coding create`), QA, Performance и DevOps пока не подключены к сценариям — это написано на их карточках.

### Как подключить проект

Любой пользователь может подключить проект одним из трёх способов. Чтобы проекты создавали только администраторы, задайте `AI_CODING_SERVER_PROJECT_CREATORS=admins`.

| Способ | Что происходит |
| --- | --- |
| **Папка с компьютера** | Браузер упаковывает выбранную папку в tar и отправляет на сервер (`POST /projects/upload`). Не загружаются `node_modules`, виртуальные окружения, кэши, локальное состояние `.ai-coding/` и `.git`. Сервер создаёт новый репозиторий: одна ветка `main`, один коммит от имени пользователя. Чужой `.git` не принимается, потому что его конфигурация может заставить git выполнять команды на сервере. Лимит размера — `AI_CODING_SERVER_MAX_UPLOAD_MB` |
| **Git-репозиторий** | Сервер клонирует репозиторий по `https://`, `ssh://` или `git@host:path`. Для приватного репозитория укажите в форме токен доступа (GitHub: fine-grained token с правом «Contents: Read-only»). Работает только с `https://`. Токен передаётся git через окружение и не попадает ни в БД, ни в журнал, ни в `.git/config` клона |
| **Папка на сервере** | Доступна, если задана `AI_CODING_SERVER_ALLOWED_ROOTS`. Каталог не может принадлежать двум проектам: занят тот, что совпадает с каталогом другого проекта, содержит его или лежит внутри. Имя чужого проекта форма не показывает. Каталоги под разрешёнными корнями — общий пул для всех пользователей |

Загруженные и склонированные проекты хранятся в `<AI_CODING_SERVER_DATA_DIR>/projects/` и удаляются вместе с проектом. Папки на сервере остаются на месте.

### Код и чат с ИИ: Claude Code и Codex, как в VS Code

Решения описаны в [ADR-0036](adr/0036-workspaces-and-browser-terminal.md) (рабочие области, терминал) и [ADR-0037](adr/0037-ai-chat-agents.md) (чат). На странице проекта нажмите «Код и терминал», затем «Открыть мою рабочую область».

- **Рабочая область** — ваша собственная копия репозитория проекта: файлы, ветки, коммиты. Другие участники её не видят.
- **Чат с ИИ** (панель справа), как в расширениях Claude Code и Codex для VS Code.
  - Выберите агента (Claude Code или Codex) и **режим работы**, затем опишите задачу. Ответ приходит потоком, действия агента сворачиваются в строку «Действия: N», подробности — по нажатию.
  - **Режимы работы** закреплены за чатом. Агент работает строго по процессу режима, а задачу из другого режима предлагает сделать в новом чате.

    | Режим | Что делает агент | Согласование |
    |---|---|---|
    | Создание | Новый проект: требования, архитектура и ADR, бэклог, каркас в ветке `ai/bootstrap` | План каждого этапа утверждаете вы |
    | Разработка | Функция или задача: план, ветка `ai/<задача>`, код и тесты, коммит | Сначала план |
    | Модернизация | Рефакторинг без изменения поведения: тесты до, шаги `M-01`, `M-02`… отдельными коммитами | Сначала план, затем по шагу |
    | Аудит | Отчёт по безопасности, качеству, архитектуре и тестам с приоритетами | Только чтение: изменения запрещены |
    | Сопровождение | Ошибки и зависимости: тест на ошибку, исправление, проверка | Сначала план |

    - В режимах, которые меняют код, Claude Code сначала составляет план (режим плана) и показывает карточку «План работы»: «Утвердить план» или «Доработать». До утверждения он файлы не меняет.
    - Codex показывает план сообщением. До утверждения каждая его правка требует разрешения; при «Править файлы без вопросов» и «Полном доступе» файлы он читает без вопросов. Утвердить — кнопка «Утвердить план и выполнить».
    - В «Аудите» у Claude Code нет инструментов записи. Файлы агенты читают без вопросов: инструментами чтения и командами вроде `cat`, `sed -n`, `grep`, `rg`, `find`, `git log/diff`. Любые другие действия отклоняются, а если файлы всё же изменились, чат предупредит.
  - **Оркестратор из чата** ([ADR-0038](adr/0038-orchestrator-tools-for-chat-agents.md)). У агента есть инструменты платформы (MCP-сервер `platform`):
    - `audit` запускает аудит платформы: Semgrep, Gitleaks, Trivy/OSV, линтеры и тесты в песочнице, находки с доказательствами, Quality Gates. По умолчанию проверяется последний коммит текущей ветки вашей рабочей области (незакоммиченное не проверяется), можно и дерево проекта.
    - `run_status` и `run_report` — ход run'а и его результаты; агент разбирает находки и исправляет их.
    - `start_task` передаёт задачу собственным агентам оркестратора (`develop`, `maintain`: ветка или PR в проекте). Работает, только если у проекта настроен ИИ-провайдер (`.ai-coding.yml`), и только после вашего разрешения в чате.
    - Режимы используют их сами: «Аудит» строит отчёт на находках платформы, «Разработка», «Сопровождение» и «Создание» перед отчётом проходят Quality Gates, «Модернизация» сравнивает аудит до и после.
    - Агент действует с вашими правами и только в этом проекте. Run'ы видны в проекте (ссылка `#/runs/<id>` в чате кликабельна), а утверждаете их только вы, в веб-интерфейсе.
  - Для действий, на которые нужно разрешение, прямо в карточке есть кнопки «Разрешить», «Разрешить в этой сессии», «Отклонить».
  - Разрешения: «Спрашивать разрешения», «Править файлы без вопросов», «Полный доступ». В «Аудите» — только чтение. «Остановить» прерывает ход.
  - История чатов сохраняется. Агент **работает в фоне**: закройте страницу, вернитесь — продолжение и вопросы будут ждать в чате.
  - **Несколько чатов во вкладках** ([ADR-0042](adr/0042-chat-tabs-and-plan-limits.md)). «+» — новый чат, «Все чаты» — открыть любой чат во вкладке или удалить его.
    - Вкладка в фоне показывает, что агент работает или ждёт вашего ответа.
    - Закрыть вкладку (×) — не остановить агента: чат остаётся во «Всех чатах».
    - Удалить чат можно, когда агент не работает. Переписка удаляется, файлы рабочей области остаются.
  - **Лимиты подписки** — значок в шапке чата, например «5 ч 4% · нед. 58%». По нажатию — сколько израсходовано и осталось в окне 5 часов и за неделю (у Claude — и по отдельным моделям), когда сброс и сколько до него.
    - Лимиты сообщают сами CLI: `/usage` у Claude Code, rate limits у Codex.
    - При входе через Anthropic Console или по API-ключу лимитов подписки нет: показывается то, что сообщает CLI.
    - Вкладки в фоне, удаление и лимиты появятся после «Перезапустить среду», когда образ рабочей области обновлён.
  - Официальные `claude` и `codex` запускает фоновая служба `ai-coding-agent` в вашем контейнере. Платформа видит их события, но не ваши учётные данные.
- **Вход в аккаунт** — только через официальные потоки вендоров. Вход хранится в вашей домашней папке на сервере, другие его не видят.
  - **Claude Code:** кнопка в чате открывает терминал с `claude auth login` (подписка Pro/Max) или `claude auth login --console` (Anthropic Console, оплата по API).
  - **Codex:** «Войти через ChatGPT» показывает ссылку и код. Подтвердите вход на сайте OpenAI.
  - **Правила вендоров.** Anthropic запрещает сторонним приложениям пропускать через себя вход claude.ai и отправлять запросы по подписке от имени пользователей. При этом прямо разрешает пользователю входить своей подпиской в неизменённый Claude Code, размещённый на платформе. Чат платформы управляет именно неизменённым CLI в вашей среде, но собственный интерфейс поверх него в правилах прямо не описан. Для использования всей организацией надёжнее вход через Anthropic Console или API-ключ OpenAI либо подтверждение вендоров.
- **Редактор.** Подсветка синтаксиса, Ctrl+S сохраняет. Файлы, которые изменил агент, перечитываются сами, если в редакторе нет несохранённых правок. Если файл изменился, пока вы его правили, сохранение не затрёт изменения: редактор предложит загрузить файл заново.
- **Терминал** (кнопка «Терминал») — тот же контейнер: `claude`, `codex`, git, Node.js, Python. Сеанс tmux сохраняется, если закрыть вкладку.
- **«Перезапустить среду»** (в чате, когда соединение закрыто) — новый контейнер из текущего образа, например после обновления платформы. Файлы, вход и история чатов сохраняются, работающие агенты и терминалы останавливаются.
- **Git.**
  - «Зафиксировать» — коммит в текущую ветку рабочей области.
  - «Обновить из проекта» — `git fetch project` и fast-forward.
  - «Отправить в проект» — ветка рабочей области попадает в репозиторий проекта как `ws/<пользователь>/<ветка>`, ветки проекта не меняются.
  - Отправка в GitHub — из терминала: `git push origin <ветка>` с вашим токеном.
  - Git рабочей области выполняется только в вашем контейнере, сервер его не запускает.
- **Изоляция контейнера.**
  - Корневая ФС только для чтения, без capabilities, без сокета Docker, лимиты CPU, памяти и процессов, опционально gVisor.
  - Сеть — только через allowlist-прокси (`AI_CODING_SERVER_WORKSPACE_EGRESS`). По умолчанию открыты Anthropic, OpenAI/ChatGPT, GitHub, GitLab, npm и PyPI. Git по SSH недоступен — используйте HTTPS.
  - Контейнер без подключённого терминала, открытого чата и работающего агента дольше `AI_CODING_SERVER_WORKSPACE_IDLE_MINUTES` удаляется. Рабочая область, вход и история чатов остаются.
  - Несколько экземпляров платформы на одном Docker не трогают контейнеры друг друга (метка экземпляра).

Подготовка (один раз и после каждого обновления платформы). Соберите образ рабочей области (Claude Code, Codex, служба чата) и скачайте образ сетевого прокси:

```bash
docker compose -f deploy/docker-compose.yml --profile build build workspace-image
```

```bash
docker pull mirror.gcr.io/library/python@sha256:e695ab189fa2d082b1c61c69a6b888a5adeca61ceeccad107b1ed2a125721a9e
```

Для аудитов (из чата и из веб-интерфейса) скачайте закреплённые образы анализаторов и офлайн-базы уязвимостей Trivy и OSV. Песочницы сами ничего не скачивают. Базы лежат в `${AI_CODING_DATA}/cache` (`AI_CODING_CACHE_DIR`), их переживают перезапуски контейнеров. Повторяйте после обновления платформы, а с `--refresh` — для свежего снимка баз. Без `-t` скачиваются образы всех стеков (PHP, Node, Go, Rust, Playwright — несколько гигабайт).

```bash
docker compose -f deploy/docker-compose.yml exec worker ai-coding tools pull -t semgrep -t gitleaks -t ruff -t mypy -t trivy -t osv-scanner
```

mypy и тесты проекта устанавливают зависимости проекта, поэтому песочнице нужна сеть. По умолчанию её нет (`execution.docker.network: none`, `security.network: local-only`), и аудит помечает эти проверки как пропущенные. Открыть доступ можно только через allowlist в `.ai-coding.yml` проекта ([ADR-0033](adr/0033-sandbox-egress-and-e2e-tools.md)):

```yaml
execution:
  docker: { network: bridge }
security:
  network: allowlist
  egress_allowlist: [pypi.org, files.pythonhosted.org]
```

В `deploy/.env` задайте `AI_CODING_SERVER_WORKSPACE_SECRET` (`openssl rand -hex 32`). Контейнеры терминалов запускает сервис `workspace` с доступом к Docker. У API этого доступа нет: он обращается к сервису с подписанными тикетами. Без Docker (`serve --with-worker`) образ собирается командой `docker build -t ai-coding-workspace:local deploy/workspace`, и API запускает контейнеры сам.

## Локальный запуск без Docker

```bash
uv sync --extra server
```

```bash
ai-coding server migrate
```

```bash
ai-coding server user add admin --admin
```

```bash
ai-coding server serve --with-worker --ui web/dist
```

`--with-worker` запускает worker в процессе API (удобно для одного хоста). Для нескольких worker'ов запускайте `ai-coding server worker` отдельно.

`serve --workers N` запускает N процессов API на одном порту. Один процесс Python упирается в GIL примерно на 100 запросах в секунду, поэтому разумно брать один процесс на ядро, оставив ядра worker'ам. С `--with-worker` этот режим несовместим. Rate limiter работает в каждом процессе отдельно, поэтому лимит умножается на N. Web UI собирается командой `npm ci && npm run build` в `web/`.

## Настройки

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `AI_CODING_SERVER_DATA_DIR` | `~/.local/share/ai-coding-server` | Клоны проектов, SQLite, артефакты |
| `AI_CODING_SERVER_DATABASE_URL` | `sqlite:///<data dir>/server.db` | В production — `postgresql+psycopg://…` (extra `postgres`) |
| `AI_CODING_SERVER_WORKERS` | `10` | Параллельных прогонов на процесс worker'а (1…256, NFR-02) |
| `AI_CODING_SERVER_ALLOWED_ROOTS` | пусто | Каталоги на сервере, которые можно регистрировать как проекты (через `:`). Пусто — только загрузка папки и клон по Git URL |
| `AI_CODING_SERVER_PROJECT_CREATORS` | `all` | Кто создаёт проекты: `all` — любой пользователь, `admins` — только администраторы |
| `AI_CODING_SERVER_MAX_UPLOAD_MB` | `500` | Наибольший размер папки, загружаемой из Web UI. В `deploy/Caddyfile` для этого пути установлен предел 2 ГБ |
| `AI_CODING_SERVER_WORKSPACES` | `local` | Терминалы рабочих областей: `local` — их запускает этот процесс (нужен Docker), URL — сервис `server workspaces` (docker-compose), `off` — выключены |
| `AI_CODING_SERVER_WORKSPACE_SECRET` | пусто | Подписывает запросы API к сервису рабочих областей; одинаковый у обоих |
| `AI_CODING_SERVER_SECRET_KEY` | пусто | Ключ шифрования секретов проектов (токен GitHub, ключ ИИ, секреты webhook): 64 hex-символа, `openssl rand -hex 32`. Одинаковый у API и worker'а. Пусто — секреты из веба не сохраняются |
| `AI_CODING_SERVER_WORKSPACE_IMAGE` | `ai-coding-workspace:local` | Образ терминала (`deploy/workspace/`) |
| `AI_CODING_SERVER_WORKSPACE_EGRESS` | Anthropic, OpenAI, GitHub, GitLab, npm, PyPI | Хосты, доступные из терминала, через запятую (`*.example.org` — поддомены); `*` — без ограничений |
| `AI_CODING_SERVER_WORKSPACE_RUNTIME` | пусто | OCI runtime контейнеров терминала, например `runsc` (gVisor) |
| `AI_CODING_SERVER_WORKSPACE_MEMORY_MB` / `_CPUS` | `4096` / `2` | Лимиты контейнера терминала |
| `AI_CODING_SERVER_WORKSPACE_IDLE_MINUTES` | `60` | Через сколько минут без подключённого терминала контейнер удаляется |
| `AI_CODING_SERVER_SECURITY_CENTER` | `off` | AI Security Center (только чтение): `on` — API и раздел Web UI, `off` — их нет. Другое значение останавливает запуск. См. [security-center.md](security-center.md) |
| `AI_CODING_SERVER_RATE_LIMIT` | `120` | Запросов в минуту на пользователя или токен |
| `AI_CODING_SERVER_LOGIN_RATE_LIMIT` | `10` | Попыток входа в минуту с одного адреса |
| `AI_CODING_SERVER_TRUSTED_PROXIES` | пусто | Адреса или имена proxy, которым доверяется `X-Forwarded-For`/`-Proto` |
| `AI_CODING_SERVER_METRICS_TOKEN` | пусто | Отдельный секрет для `/metrics`; пусто — только администратор |
| `AI_CODING_SERVER_RETENTION_DAYS` | `0` | Срок хранения завершённых прогонов. `0` — срок из `artifacts.retention_days` проекта при `server purge` |

| `AI_CODING_SERVER_DB_POOL_SIZE` / `AI_CODING_SERVER_DB_MAX_OVERFLOW` | `10` / `10` | Соединения PostgreSQL на один процесс: постоянные / дополнительные под нагрузкой |

`ai-coding server settings` показывает действующие значения без секретов.

**Размер пула.** Сумма по всем процессам — API-процессы `serve --workers N` плюс worker'ы — не должна превышать `max_connections` PostgreSQL (по умолчанию 100): `процессы × (POOL_SIZE + MAX_OVERFLOW) < max_connections`. При превышении PostgreSQL отказывает в соединении (`too many clients`), и запросы завершаются ошибкой 500. Нагрузочный тест воспроизвёл это при пуле 10 + 30 на 4 процесса.

## Роли и изоляция проектов

Роль назначается в каждом проекте отдельно. Права проверяет сервер (ТЗ §3), а не UI.

| Право | owner | maintainer | developer | auditor | agent |
| --- | :-: | :-: | :-: | :-: | :-: |
| Просмотр проекта, прогонов, находок, артефактов | ✅ | ✅ | ✅ | ✅ | ✅ |
| Прогоны discover/audit | ✅ | ✅ | ✅ | — | — |
| Прогоны с изменениями (develop/maintain) | ✅ | ✅ | ✅ | — | — |
| Отмена своих прогонов | ✅ | ✅ | ✅ | — | — |
| Отмена любых прогонов, approve/reject | ✅ | ✅ | — | — | — |
| Журнал аудита | ✅ | ✅ | — | ✅ | — |
| Просмотр файлов проекта в Web UI | ✅ | ✅ | ✅ | ✅ | — |
| Рабочая область: терминал, правка файлов, коммиты | ✅ | ✅ | ✅ | — | — |
| Участники, экспорт, удаление проекта | ✅ | — | — | — | — |

- Проекты создают сами пользователи (или только администраторы при `AI_CODING_SERVER_PROJECT_CREATORS=admins`), создатель становится owner'ом. Токен, ограниченный проектом или ролью ниже owner, проекты не создаёт.
- Администратор сервера (`--admin`) управляет пользователями. К чужим проектам неявного доступа у него нет: его, как и любого пользователя, должен добавить owner (принцип наименьших привилегий, `api/rbac.py`).
- **Чужой проект неотличим от несуществующего.** На любой объект другого проекта (проект, прогон, артефакт, находки, журнал) ответ — `404` с тем же телом, что и для отсутствующего объекта. `403` возвращается только участнику проекта, у которого не хватает роли.
- Каждая операция и каждый отказ записываются в журнал аудита: actor, project_id, run_id, время, результат. Отказы сохраняются отдельной транзакцией и не откатываются вместе с запросом.
- Последнего owner'а проекта нельзя удалить или понизить.

## Токены API

```bash
ai-coding server token create ci-bot --name nightly --project <project-id> --role auditor --ttl-hours 720
```

- Токен показывается один раз (`aic_…`); в БД хранится только SHA-256.
- Токен с `--project` действует только в этом проекте. `--role` ограничивает права сверху: роль токена — меньшая из роли пользователя и `--role`.
- Токены роли `agent` обязаны быть привязаны к проекту и живут не дольше 24 часов (ТЗ §3: «ограниченно, короткоживуще»).
- Токен, ограниченный проектом, не может выпускать новые токены.
- Токены входа (`POST /auth/login`) живут 12 часов, остальные — 30 дней по умолчанию.

## Подключение CLI разработчика (Local)

`ai-coding` на своей машине работает автономно, со своей SQLite. После подключения сервер получает сводки его прогонов, и они видны на странице «Инфраструктура» в карточке «Local (CLI)» ([ADR-0047](adr/0047-local-cli-reports.md)).

```bash
ai-coding server login --url http://10.0.1.115:8090   # спросит токен: Web UI → Аккаунт → Токены
cd ~/src/my-project && ai-coding server link my-project
ai-coding audit                                        # в конце: «run 1a2b3c4d reported to …»
```

- Отправляется только сводка: состояние, вердикт, гейты, число новых находок по уровням, ветка, коммит, машина. Код, пути и тексты находок остаются на машине.
- Вход хранится в `~/.config/ai-coding/server.json` (права `0600`), привязка — в `.ai-coding/server.json` проекта (не коммитится). В CI вместо них задайте `AI_CODING_REMOTE_URL`, `AI_CODING_REMOTE_TOKEN` и `AI_CODING_REMOTE_PROJECT`.
- Сервер недоступен — команда всё равно завершается со своим результатом, а прогон можно отправить позже: `ai-coding server report [RUN]`.
- Ещё команды: `ai-coding server whoami`, `unlink`, `logout`. Отчитываться может участник с правом запускать прогоны (`run.create`).
- По HTTP (не HTTPS) токен идёт открытым текстом — CLI об этом предупреждает. Для доступа из-за пределов локальной сети включите TLS (Caddy).

## REST API

Базовый путь `/api/v1`. Документ OpenAPI — `/api/v1/openapi.json`, интерактивная документация — `/api/docs`. Аутентификация: `Authorization: Bearer <token>`.

| Метод и путь | Назначение |
| --- | --- |
| `POST /auth/login`, `GET /me` | Вход, текущий пользователь и его проекты |
| `PUT /me/password` | Смена своего пароля (нужен текущий) |
| `GET/POST /tokens`, `POST /tokens/{id}/rotate`, `DELETE /tokens/{id}` | Токены API |
| `GET/POST /users` | Список и создание пользователей (администратор) |
| `PATCH /users/{username}` | Имя, права администратора, блокировка (администратор). Блокировка отзывает все токены пользователя. Себя заблокировать или понизить нельзя |
| `PUT /users/{username}/password` | Новый пароль пользователя (администратор) |
| `GET/POST /projects`, `GET/DELETE /projects/{id}` | Проекты (ТЗ §13: `POST /projects`): `git_url` (+ `branch`, `git_token` для приватного репозитория) или `path`. `GET /projects/{id}` возвращает и `config` — сводку конфигурации без секретов (стеки, режим, исполнение, ИИ, сеть, бюджеты, Quality Gates); `null`, если конфигурация не читается или невалидна |
| `POST /projects/upload?name=…` | Проект из папки: тело — несжатый tar (`Content-Type: application/x-tar`), не больше `AI_CODING_SERVER_MAX_UPLOAD_MB` |
| `GET /project-sources` | Откуда можно подключить проект: Git, лимит загрузки, свободные и занятые каталоги в `AI_CODING_SERVER_ALLOWED_ROOTS` |
| `GET/POST /projects/{id}/workspace` | Своя рабочая область: состояние, создание |
| `GET /projects/{id}/files?path=&scope=`, `GET/PUT/DELETE /projects/{id}/file?path=` | Файлы рабочей области (`scope=project` — файлы проекта, только чтение); `PUT` с `version` — 409, если файл изменился |
| `GET /projects/{id}/workspace/git`, `POST …/commit`, `POST …/pull`, `POST …/publish` | Git рабочей области (выполняется в контейнере пользователя). `commit` с `staged_only: true` фиксирует только принятое в проверке |
| `WS /projects/{id}/workspace/terminal` | Терминал: первое сообщение `{"token", "cols", "rows"}`, затем `{"type": "input"\|"resize"}` |
| `GET /projects/{id}/workspace/diff` | Изменения рабочей области для проверки: `accepted` (индекс), `pending` (рабочее дерево), `new_files`; файлы с фрагментами и патчем каждого фрагмента (ADR-0040) |
| `POST /projects/{id}/workspace/review` | `{action: accept\|reject\|unstage, patch}` или `{action: accept_file\|reject_file, path}`. 409 — фрагмент больше не накладывается |
| `WS /projects/{id}/workspace/chat` | Чат с ИИ: первое сообщение `{"token"}`, затем операции `hello`, `new` (с `workflow`: `create`, `develop`, `modernize`, `audit`, `maintain`; `ref` вкладки), `open`, `close`, `delete`, `send` (с `approve_plan`), `approve`, `interrupt`, `login`, `usage` (лимиты подписки) (ADR-0037, ADR-0042) |
| `POST /projects/{id}/workspace/restart` | Перезапустить свой контейнер рабочей области (новый — из текущего образа) |
| `PUT/DELETE /projects/{id}/members/{username}` | Роли участников |
| `GET /projects/{id}/export` | ZIP со всеми данными проекта (NFR-08) |
| `GET /kinds`, `GET/POST /projects/{id}/runs` | Типы прогонов, список и запуск (ТЗ §13) |

**Идемпотентность.** `POST /projects` и `POST /projects/{id}/runs` принимают заголовок `Idempotency-Key`. Повтор с тем же телом возвращает исходный ответ с `Idempotent-Replayed: true`. Тот же ключ с другим телом или путём — `422`. Ключи хранятся сутки.

**Ошибки** имеют единый вид `{"error": {"code": "...", "message": "..."}}`. `429` приходит с заголовком `Retry-After`, `413` — для тела больше 1 МБ (для `POST /projects/upload` — больше `AI_CODING_SERVER_MAX_UPLOAD_MB`).

## Безопасность HTTP (NFR-04)

- TLS терминирует Caddy с автоматическими сертификатами. API доверяет `X-Forwarded-*` только от адресов из `AI_CODING_SERVER_TRUSTED_PROXIES`. HSTS выставляется только для HTTPS-запросов.
- Заголовки: `Content-Security-Policy` (`default-src 'self'`, без inline-скриптов), `X-Content-Type-Options`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, `Cache-Control: no-store` для `/api/`.
- Rate limiting — на пользователя/токен и отдельно на вход с одного адреса. Тип задаёт `AI_CODING_SERVER_RATE_LIMIT_BACKEND`:
  - `auto` (по умолчанию) — лимит **общий** для всех процессов API и реплик на PostgreSQL, а также при `serve --workers N` на SQLite: счётчики хранятся в БД (таблица `rate_limit_counters`, ключи — SHA-256). Один процесс на SQLite считает в памяти.
  - `memory` и `database` задают тип явно. `memory` при нескольких процессах даёт каждому полный лимит, об этом пишется предупреждение в лог.

  Общий лимитер считает по скользящей минуте. Каждый процесс накапливает счёт локально и раз в 0,5 с добавляет его в БД атомарным upsert. Поэтому за одно окно синхронизации процесс может пропустить запросов не больше, чем «скорость × 0,5 с». Запись в БД на каждый запрос выстраивала запросы в очередь на блокировке строки: в нагрузочном тесте p95 вырос с 0,4 до 1,9 с. Если БД недоступна, решает локальный счёт процесса, а к БД лимитер возвращается после паузы (1 → 30 с), не задерживая запросы.
- Web UI хранит токен в `sessionStorage` и отправляет его заголовком. Cookie не используются, поэтому CSRF неприменим.

## Очередь и worker'ы

- Прогон создаётся в API и ставится в очередь (`run_jobs`). Worker берёт задание под lease: в PostgreSQL через `FOR UPDATE SKIP LOCKED`, в SQLite через compare-and-set. Lease продлевается heartbeat'ом.
- Если worker упал, lease истекает. Задание забирает другой worker и продолжает прогон с последнего checkpoint (`resume`). После трёх неудачных попыток задание помечается `failed`.
- Approval останавливает прогон в `WAITING_APPROVAL`. Решение через `POST /runs/{id}/approve` ставит в очередь `resume`, когда ожидающих approvals не остаётся.
- `AI_CODING_SERVER_WORKERS` задаёт число параллельных прогонов на процесс. Масштабирование — дополнительные контейнеры `worker`.
- Каждые 15 с worker записывает heartbeat в `<каталог данных>/workers/` и удаляет его при остановке. Поэтому «Инфраструктура» и Mission Control показывают и простаивающие worker'ы. Worker без heartbeat'а дольше минуты считается не в сети. Worker'у нужна запись в каталог данных, которым он и так делится с API (исходники прогонов).
- `SIGTERM` и `SIGINT`: worker перестаёт брать задания и дожидается текущих.

## Изоляция worker'а: rootless Docker и удалённый демон

Доступ к Docker-демону эквивалентен root на его хосте. API доступа к демону не имеет, но worker должен его иметь, чтобы запускать песочницы. Для production рекомендуется один из вариантов:

- **Rootless Docker** на хосте worker'а: демон работает от непривилегированного пользователя, и захват демона не даёт root на хосте. Worker найдёт демон через `DOCKER_HOST=unix:///run/user/<uid>/docker.sock` или `docker context use rootless` (`DOCKER_CONTEXT`). Файлы, которые песочница создаёт во временных каталогах, получают в rootless-режиме uid из диапазона subuid. Хост не может их удалить, поэтому их удаляет сам пользователь песочницы (`tools/scratch.py`).
- **Удалённый демон** (отдельная машина или VM для песочниц): `DOCKER_HOST=tcp://builder:2376` с `DOCKER_TLS_VERIFY=1` и `DOCKER_CERT_PATH`, либо `DOCKER_HOST=ssh://user@builder` с `SSH_AUTH_SOCK`. Пути монтирования интерпретирует демон, поэтому каталог данных (`AI_CODING_SERVER_DATA_DIR`, клоны и временные каталоги) и `TMPDIR` должны быть доступны демону **по тем же путям** — например, через общий NFS-том.

Executor передаёт `docker` CLI только эти переменные (`DOCKER_HOST`, `DOCKER_CONTEXT`, `DOCKER_TLS_VERIFY`, `DOCKER_CERT_PATH`, `SSH_AUTH_SOCK`, `XDG_RUNTIME_DIR` и т. п.). Секреты процесса платформы — ключи провайдеров, S3, GitHub — в окружение `docker` не попадают.

## Артефакты в MinIO / S3

В `.ai-coding/config.yml` проекта укажите `artifacts.store: minio` и задайте переменные worker'у и API:

| Переменная | Пример |
| --- | --- |
| `AI_CODING_S3_ENDPOINT` | `https://minio.internal:9000` |
| `AI_CODING_S3_BUCKET` | `ai-coding` |
| `AI_CODING_S3_ACCESS_KEY_ID` / `AI_CODING_S3_SECRET_ACCESS_KEY` | ключи сервисной учётной записи |

В CI хранилище проверяется на настоящем S3-совместимом сервере VersityGW, который сам проверяет подписи: операции, постраничный `ListObjectsV2`, неверные ключи (`SignatureDoesNotMatch`), подмена объекта и серверный прогон с артефактами в bucket'е.

## Резервное копирование и восстановление

```bash
deploy/backup.sh /var/backups/ai-coding 14
```

Скрипт делает `pg_dump` в gzip с правами `0600` и удаляет копии старше 14 дней. Запускайте его из cron. Восстановление:

```bash
gunzip -c /var/backups/ai-coding/aicoding-<время>.sql.gz | docker compose -f deploy/docker-compose.yml exec -T postgres psql -U aicoding -d aicoding
```

Каталог данных (`AI_CODING_DATA`: клоны и локальные артефакты) копируйте средствами файловой системы. Артефакты в MinIO — политиками bucket'а.

## Экспорт и удаление данных (NFR-08)

- `GET /projects/{id}/export` (owner) или `ai-coding server export <project> --user <owner> --output project.zip`. ZIP содержит проект, прогоны, задачи, approvals, события, находки, учёт LLM, журнал аудита и файлы артефактов.
- `DELETE /projects/{id}` (owner) удаляет данные проекта и его артефакты, а также клон, если сервер сам его создавал. Каталоги из `ALLOWED_ROOTS` не удаляются. Пока есть активные прогоны, удаление возвращает `409`. Журнал аудита сохраняется.
- Retention: `ai-coding server purge` (для cron) или автоматически раз в час в worker'е при `AI_CODING_SERVER_RETENTION_DAYS > 0`. Удаляются завершённые прогоны старше срока, их неиспользуемые артефакты, просроченные ключи идемпотентности и токены, отозванные или истёкшие более 30 дней назад.

## Производительность и нагрузочный тест (NFR-02)

```bash
uv run python loadtest/run_load.py --out load-out
```

Скрипт поднимает PostgreSQL (одноразовый, по digest), API (`serve --workers 2`) и два процесса worker'ов по 10 прогонов. Затем запускает k6 (образ по digest) со сценарием `loadtest/server.js`. Сценарии работают одновременно:
- поток чтения API;
- 60 discovery-прогонов от 30 пользователей, каждый опрашивается раз в секунду до завершения;
- раз в 200 мс считывается `aicoding_jobs{state="leased"}` — число прогонов, выполняющихся в этот момент на всех worker'ах.

Пороги, при нарушении которых k6 завершается с кодом 99:
- ≥ 10 одновременных прогонов;
- все прогоны завершены, неуспешных нет;
- ошибок чтения < 1 %;
- p95 чтения < 500 мс.

CI запускает тест в job «Load test (k6)», итоги попадают в summary job'а.

Измерено на 4 vCPU, где API, worker'ы, PostgreSQL и k6 работают на одной машине (S9):

| Профиль | Запросов/с | p95 / p99 чтения | Прогоны | Одновременно |
| --- | --- | --- | --- | --- |
| По умолчанию: 15 итераций чтения/с, опрос раз в 1 с | 54 | 371 / 581 мс | 60 из 60 | 20 |
| Перегрузка: 40 итераций/с, опрос каждые 250 мс (`--read-rate 40 --poll-seconds 0.25`) | 92 | 1813 / 2142 мс | 60 из 60 | 20 |

Под перегрузкой растёт задержка, но ошибок нет и все прогоны завершаются. Предел одного процесса API — около 200 запросов в секунду на ядро (≈ 4,7 мс CPU на запрос). На общей машине его делят с worker'ами, поэтому для большего трафика добавляйте процессы API и выносите worker'ы на отдельные хосты.
