Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии — [SemVer](https://semver.org/lang/ru/). Номер версии совпадает с версией ТЗ, которую реализует релиз.

## [Unreleased]

### Исправлено

- **Сканер, превысивший лимит времени, завершается понятной ошибкой, даже если Docker не отвечает.** Раньше при перегруженном демоне (например, во время сборки образов) `docker kill` сам зависал. Тогда шаг падал с `TimeoutExpired: … docker kill … timed out after 30 seconds` вместо сообщения о таймауте сканера, а клиент `docker run` оставался работать. Теперь клиент останавливается всегда, шаг завершается таймаутом, а в выводе сказано, что контейнер мог остаться.
- **Codex в чате не спрашивает разрешения на чтение, пока строит план.** Раньше при «Полном доступе» в режимах с планом Codex спрашивал о каждой команде, даже о `cat` и `git status`. А в «Аудите» его читающие команды отклонялись: Codex запускает их как `/usr/bin/bash -lc '…'`, и служба чата не узнавала оболочку по полному пути. Теперь читающие команды проходят без вопросов, изменения по-прежнему ждут утверждённого плана; при «Спрашивать разрешения» вопросы остаются.
- **Audit Center, Mission Control и «Проекты» считают находки один раз.** Раньше одна и та же находка учитывалась в каждом аудите, где она встречалась: 14 находок trivy в пяти аудитах давали «70 открытых». Теперь обзор, категории и счётчики показывают последний аудит каждого проекта (`GET /findings?current=true`), а тренд и история находки — все аудиты. Находки, принятые через baseline, получают статус `baselined` и не считаются открытыми. Тесты покрывают каждую вкладку Audit Center.
- **Секреты сервера нельзя вывести через `.ai-coding.yml`.** Раньше `ai.api_key_env` проекта мог назвать любую переменную окружения worker'а, например `AI_CODING_SERVER_DATABASE_URL` или `AI_CODING_S3_SECRET_ACCESS_KEY`, а `base_url` — свой сервер. Запуск отправлял туда её значение как ключ модели. Теперь на сервере переменные `AI_CODING_*` в ключах модели запрещены (кроме собственного веб-ключа проекта): запуск и проверка подключения получают 422 с объяснением ([ADR-0046](docs/adr/0046-ai-providers-from-web.md)).
- **Несохранённые правки не пропадают из редактора.** Раньше после перехода на Chat в AI Workspace или на «Изменения» в Code Studio и обратно редактор показывал файл без правок, хотя они оставались несохранёнными. Теперь он открывается с ними.
- **Простаивающие worker'ы видны.** Раньше «Инфраструктура» показывала «Docker workers 0», пока worker ждал заданий: worker'ы определялись только по арендам заданий. Теперь worker отмечается heartbeat'ом в каталоге данных. `GET /system` отдаёт по каждому worker'у `online`, `host`, `started` и `concurrency`, Mission Control считает worker'ы в сети.
- **Долгие команды в чате рабочей области не выглядят зависшими.** Видно, что выполняется и сколько идёт. Через минуту появляется пояснение, а если агент ждёт ответа — «ждёт вашего решения». В образе рабочей области есть `uv`, так что агенту не нужно ставить его через pip.

### Добавлено

- **Карточка агента открывается** (`#/agents?agent=<имя>`). Видны все задачи агента в проекте: статус каждой попытки, шаг и run (со ссылкой), номер попытки, время начала, длительность, токены, стоимость, модели и текст ошибки. Сверху итоги: запуски, успешные, с ошибкой, в работе, расход и среднее время. Задачи фильтруются по статусу. Так же открываются встроенные шаги оркестратора.
- **Деплой из платформы** ([ADR-0048](docs/adr/0048-deploy-adapter.md)).
  - Среды проекта: GitHub Actions (workflow с `workflow_dispatch`) или подписанный webhook (`X-AI-Coding-Signature: sha256=HMAC`, секрет среды `deploy.<имя>.webhook`), необязательная проверка здоровья, требование пройденных Quality Gates.
  - Деплой — run вида `deploy`. Production и среды «с подтверждением» ждут approve владельца или мейнтейнера; в вебе Production подтверждается вводом имени среды.
  - Страница «Деплой и среды»: карточки сред, «Задеплоить», история, редактор сред.
  - Адреса webhook и проверки здоровья — только https на публичные адреса (защита от SSRF и DNS rebinding).
- **GitHub Actions со стороны сервера** ([ADR-0043](docs/adr/0043-github-actions.md)).
  - Вкладка проекта «Интеграции»: «Включить GitHub Actions», репозиторий, ветка по умолчанию, адрес API, токен (хранится зашифрованным, не показывается) и «Проверить подключение» с понятной причиной ошибки и правами токена. Пока интеграция выключена, сервер не обращается к GitHub.
  - «Инфраструктура» показывает подключение всех ваших проектов, ошибки, ссылку «Настроить», запуски workflow текущего проекта с заданиями и запуск workflow.
- **Результаты отдельных тестов (JUnit)** ([ADR-0044](docs/adr/0044-junit-test-results.md)).
  - Тесты в песочнице (DEVELOP, MODERNIZE, MAINTAIN) пишут отчёт JUnit: платформа сама добавляет флаги для pytest, `node --test` и Vitest. Своя команда тоже даёт отчёт, если пишет его в `/deps/junit.xml`. Вывод `go test -json` и `cargo test` в аудите переводится в тот же формат. Отчёт сохраняется как артефакт `junit-*.xml`.
  - Отчёт разбирается безопасно: без DOCTYPE и сущностей, до 10 МБ, ссылки песочницы на файлы хоста не читаются, пути приводятся к путям проекта.
  - API: `GET /runs/{id}/tests`, `GET /projects/{id}/test-runs`, `GET /projects/{id}/tests/history?test=`.
  - «Тесты и Quality Gates» → «Тестовые прогоны»: итоги прогонов, наборы и тесты (упавшие первыми), регрессии относительно прошлого прогона, самые медленные тесты, история теста, «Открыть в Code Studio» на строке падения. Если отчёта нет, прогон объясняет причину и называет настройку.
  - Jest без jest-junit и PHPUnit пока не поддерживаются.
- **Вкладки редактора, Split View и вкладки рабочих областей** ([ADR-0045](docs/adr/0045-split-view-and-workspace-tabs.md)).
  - В Code Studio и на вкладке Code в AI Workspace файлы открываются вкладками. У вкладки с несохранёнными правками стоит точка ●, и закрыть её (× или средней кнопкой мыши) можно только после подтверждения. При следующем открытии проекта вкладки возвращаются. В браузере хранятся только пути, содержимое файлов — нет.
  - «Разделить редактор» показывает две группы вкладок рядом. «Открыть справа» и «Открыть слева» переносят вкладку вместе с несохранёнными правками: файл открыт только в одной группе. Границу между группами можно тянуть. Уже 900 px видна одна группа и переключатель.
  - Ссылка `#/projects/<id>/code?file=<путь>&line=<n>` открывает файл, ставит курсор на строку и подсвечивает её.
  - Над страницей — полоса вкладок открытых рабочих областей: проект и AI Workspace или Code Studio, до восьми, недавние первыми. Нажатие переключает, × закрывает.
  - Кнопка «Во весь экран» в шапке рабочей области оставляет только основную панель, Esc возвращает всё обратно.
- **ИИ-провайдер оркестратора из веба** ([ADR-0046](docs/adr/0046-ai-providers-from-web.md)).
  - Страница «Модели»: включение ИИ, провайдер (OpenAI, Anthropic, Ollama, vLLM), модель из списка провайдера, адрес, ключ, Private Mode, модели по агентам, резервные модели и бюджеты; у каждого поля видно, откуда значение — «из .ai-coding.yml» или «задано в веб».
  - Значения из веба действуют поверх `.ai-coding.yml` для запусков на сервере; локальный CLI читает только файл.
  - Ключ — зашифрованный секрет проекта `ai.api_key`, только для записи: его нет в ответах, аудите, журналах и окружении процессов.
  - Веб-ключ одного проекта недоступен другим: имя ключа `AI_CODING_*` в чужом `.ai-coding.yml` отвергается (см. «Исправлено»).
  - «Проверить подключение» — настоящий запрос списка моделей с учётом политики сети проекта.
  - Менять настройки могут владелец и мейнтейнер, остальные видят страницу только для чтения.
- **Зашифрованные секреты проекта.** Токен GitHub, ключ ИИ-провайдера и секреты webhook деплоя задаются в вебе и хранятся в БД зашифрованными (AES-256-GCM, привязка к проекту и имени секрета). Их можно только записать: API показывает последние символы, кто и когда задал, но не значение. Нужен ключ сервера `AI_CODING_SERVER_SECRET_KEY` (`openssl rand -hex 32` в `deploy/.env`), без него секреты не сохраняются. API: `GET /projects/{id}/secrets`, `PUT/DELETE /projects/{id}/secrets/{name}` (владелец, мейнтейнер); миграция `0004_project_integrations`.
- **CLI разработчика подключается к серверу** ([ADR-0047](docs/adr/0047-local-cli-reports.md)).
  - `ai-coding server login --url …` (токен из «Аккаунт → Токены»), `ai-coding server link ПРОЕКТ` в каталоге проекта. После этого каждая команда CLI в конце отправляет на сервер сводки своих прогонов.
  - Отправляется только сводка: состояние, вердикт, гейты, число новых находок по уровням, ветка, коммит, машина. Код и находки остаются на машине.
  - Если сервер недоступен, команда не падает, а прогон можно отправить позже: `ai-coding server report`.
  - API: `POST/GET /projects/{id}/local-runs`, `GET /local-runs/overview`; таблица `local_runs` (миграция `0005_local_runs`).
- **Вкладки чатов, удаление чата и лимиты подписок** ([ADR-0042](docs/adr/0042-chat-tabs-and-plan-limits.md)).
  - В панели чата открыто сразу несколько чатов, каждый во вкладке. Вкладка в фоне показывает, что агент работает или ждёт ответа. Закрытие вкладки не останавливает агента. Открытые вкладки запоминаются.
  - «Все чаты» открывают любой чат во вкладке. Там же чат удаляется, с подтверждением; пока агент работает, удалить нельзя.
  - Лимиты подписки в шапке чата: окно 5 часов и неделя (у Claude — и по моделям). Видно, сколько израсходовано и осталось, когда сброс и сколько до него. Данные дают сами CLI: `/usage` у Claude Code, rate limits у Codex.
  - Служба `ai-coding-agent`: клиент следит за всеми открытыми чатами, новые операции `close`, `delete`, `usage`, `ref` в `new`, `features` в `hello`. Нужен новый образ рабочей области и «Перезапустить среду».
- **ИИ в редакторе** ([ADR-0041](docs/adr/0041-ai-in-the-editor.md)).
  - Изменения агента подсвечены прямо в коде Code Studio и AI Workspace, у каждого фрагмента — «Принять» / «Отклонить».
  - Над выделенным кодом — «Объяснить», «Исправить», «Улучшить», «Тесты», «Спросить…» (`Ctrl+I`): запрос уходит в чат рабочей области с путём, строками и кодом.
  - Двоичные файлы и изменения без построчных фрагментов принимаются, откатываются и возвращаются на проверку целиком.
  - Редактор следует теме NEXUS.
  - Проверка `web/e2e/editor.mjs` проходит этот сценарий в настоящем контейнере.
- **AI Changes Review** ([ADR-0040](docs/adr/0040-ai-changes-review.md)): проверка изменений рабочей области по фрагментам — во вкладке Diff AI Workspace (со счётчиком непроверенного) и в «Изменениях» Code Studio.
  - Каждый фрагмент можно принять (индексируется), отклонить (откатывается в файле) или вернуть на проверку; новые файлы — принять или удалить; есть «Принять всё» и «Зафиксировать принятое» (коммит только индекса).
  - Виды «Построчно» и «Рядом».
  - API: `GET /projects/{id}/workspace/diff`, `POST /projects/{id}/workspace/review`, `staged_only` в `POST …/workspace/commit`. Git выполняется в контейнере пользователя. Решения пишутся в журнал (`workspace.review`).
  - Проверка `web/e2e/review.mjs` проходит этот сценарий в настоящем контейнере.

  - **App Shell:** боковое меню с переключателем проекта, избранным и сворачиванием; командная строка с хлебными крошками, статусом сервера и ИИ, активными задачами, согласованиями, темой и профилем; командная палитра `Ctrl/Cmd+K`; правая панель AI Copilot (чат рабочей области).

    - Задачи (фильтры, очередь согласований, создание задачи);

- **Web UI: управление сервером.** Каждый пользователь создаёт проекты сам и становится их owner'ом. Три способа: папка с компьютера (загрузка из браузера), Git-репозиторий (приватный — по токену, который не сохраняется), каталог в `AI_CODING_SERVER_ALLOWED_ROOTS`. Удаление проекта с подтверждением, роли участников прямо в таблице. Раздел «Пользователи» для администраторов: создание, права администратора, блокировка, смена пароля. Раздел «Профиль и токены»: смена своего пароля, выпуск и отзыв токенов API.
- **API:** `POST /projects/upload` (tar папки), `git_token` в `POST /projects`, `GET /project-sources`, `GET /users`, `PATCH /users/{username}` (блокировка отзывает все токены пользователя), `PUT /users/{username}/password`, `PUT /me/password`. `GET /me` возвращает `token_id` текущей сессии и `can_create_projects`.
- **Код и терминал в браузере** ([ADR-0036](docs/adr/0036-workspaces-and-browser-terminal.md)). У каждого участника своя рабочая область — клон репозитория проекта:
  - дерево файлов и редактор CodeMirror; сохранение не затирает изменения, сделанные в терминале;
  - терминал (xterm.js, tmux) в изолированном контейнере с официальными **Claude Code** и **Codex**. Пользователь входит своей подпиской Pro/Max или ChatGPT; платформа не хранит и не передаёт токены подписок;
  - git: коммит, «Обновить из проекта», «Отправить в проект» (ветка `ws/<пользователь>/<ветка>`).

  Git рабочей области выполняется только в контейнере пользователя. Сеть контейнера — через allowlist-прокси. В docker-compose контейнеры запускает новый сервис `workspace` (`ai-coding server workspaces`) с подписанными тикетами от API; образ терминала — `deploy/workspace/`. Новые права: `files.view`, `workspace.use`.
- **Чат с ИИ, как в VS Code** ([ADR-0037](docs/adr/0037-ai-chat-agents.md)): панель справа на странице «Код».
  - Claude Code (stream-json) и Codex (app-server) работают в фоне в контейнере пользователя: фоновая служба `ai-coding-agent`, история чатов, продолжение после закрытия вкладки.
  - Потоковые ответы, карточки команд и правок с diff, разрешения «Разрешить / в этой сессии / Отклонить», режимы, остановка.
  - Вход в Codex по коду ChatGPT прямо в чате, в Claude Code — официальной командой в терминале.
  - Кнопка «Перезапустить среду».
  - **Режимы работы платформы в чате:** «Создание», «Разработка», «Модернизация», «Аудит», «Сопровождение». Режим выбирается для чата, и агент работает по его процессу. Режимы, которые меняют код, начинают с плана, утверждённого пользователем (у Claude Code — его режим плана и карточка «План работы»). «Аудит» только читает: без инструментов записи, запросы на изменения отклоняются, изменённые файлы показываются предупреждением.
  - Ответ на языке вопроса; действия, размышления и код свёрнуты, видны по нажатию.
- **Оркестратор из чата** ([ADR-0038](docs/adr/0038-orchestrator-tools-for-chat-agents.md)): у Claude Code и Codex появились инструменты платформы (MCP-сервер `platform`).
  - `audit` — аудит платформы для последнего коммита ветки рабочей области или для проекта.
  - `run_status`, `run_report` — ход и результаты run'а.
  - `start_task` — задача агентам оркестратора, нужен ИИ-провайдер проекта.
  - `cancel_run` — отмена своего run'а.

  Запросы идут через почтовый ящик рабочей области (`/platform`). API выполняет их с правами пользователя в этом проекте и пишет в журнал (`workspace.agent`). Утверждать run'ы агент не может. Режимы чата используют эти инструменты в своём процессе.
- «Аудит» в чате читает файлы без вопросов: инструменты чтения Claude Code и команды, которые консервативная проверка признала читающими (`cat`, `sed -n`, `grep`, `rg`, `find`, `git log/diff`…). Остальное по-прежнему отклоняется. Раньше отклонялось любое действие, требовавшее разрешения, включая чтение.
- `deploy/docker-compose.yml`: `AI_CODING_CACHE_DIR` в каталоге данных. Офлайн-базы Trivy и OSV переживают перезапуск worker'а и монтируются в песочницы; раньше они искались в `~/.cache` контейнера.
- Run'ы `audit` и `discover` могут проверять снимок ветки рабочей области (`<data>/sources`), сохраняя конфигурацию, baseline и артефакты проекта (`StepContext.tree`).
  - Контейнеры помечаются экземпляром платформы: тестовый и боевой экземпляры на одном Docker не мешают друг другу.
- **API для Web UI (только чтение):** `GET /agents` (каталог агентов), `GET /runs` и `GET /findings` по всем доступным проектам с фильтрами, `GET /projects/{id}/agent-executions` (попытки агентов с токенами, стоимостью и моделями), `GET /projects/{id}/usage` (расход LLM по моделям и дням), `GET /system` (состояние экземпляра, только администраторы). `GET /runs/{id}` дополнен зависимостями задач, Quality Gates и расходом LLM, `GET /projects/{id}` — сводкой конфигурации без секретов. Права проверяются на сервере, как у остальных эндпоинтов проекта.
- **Настройки:** `AI_CODING_SERVER_PROJECT_CREATORS` (`all` | `admins`), `AI_CODING_SERVER_MAX_UPLOAD_MB` (500). В `deploy/Caddyfile` предел тела для загрузки папки поднят до 2 ГБ, для остальных путей остаётся 1 МБ.

### Изменено

- CSP Web UI разрешает inline-стили (`style-src 'self' 'unsafe-inline'`): их требует терминал xterm.js. Скрипты по-прежнему только `'self'`.
- В `deploy/docker-compose.yml` обязательна переменная `AI_CODING_SERVER_WORKSPACE_SECRET`.
- Проекты создают все пользователи, а не только администраторы. Прежнее поведение — `AI_CODING_SERVER_PROJECT_CREATORS=admins`.
- Каталог на сервере нельзя подключить, если он совпадает с каталогом другого проекта, содержит его или лежит внутри. Раньше один каталог можно было зарегистрировать дважды.

### Исправлено

- `docs/server.md` утверждал, что администратор имеет права owner во всех проектах; на деле доступ даёт только членство в проекте.

## [2.1.0] — 2026-11-05

Первый выпуск. Реализует ТЗ «AI Coding Platform v2.1 — Local, Self-Hosted & GitHub Hybrid». Все приёмочные сценарии AC-01…AC-10 автоматизированы и проходят в CI ([docs/acceptance.md](docs/acceptance.md)). Отчёты спринтов — [docs/sprints/](docs/sprints/).

### Режимы и сценарии

- **CREATE** (S5) — новый проект из описания: согласованная версия ТЗ, ADR, backlog, каркас в ветке, PR.
- **DEVELOP / MODERNIZE / REVIEW** (S6) — задача или issue → изменения с тестами → тесты в песочнице → AI review → ветка → PR. Модернизация малыми шагами с откатом.
- **AUDIT** (S3, S7) — read-only и офлайн:
  - секреты, SAST, зависимости (Trivy, OSV-Scanner) по офлайн-базам;
  - инструменты стеков: PHPStan, Pint, ESLint, `tsc`, mypy, `go test`, golangci-lint, `cargo test`, Clippy;
  - E2E на Playwright и нагрузка на k6 (S9);
  - Quality Gates, baseline, SARIF и JUnit.
- **MAINTAIN** (S7) — план → approval → обновление зависимостей пакетным менеджером → исправление с регрессионным тестом → PR.
- **12 агентов ТЗ §6** со схемами вывода и циклом исправления. LLM-адаптеры OpenAI, Anthropic, Ollama и vLLM с маршрутизацией, fallback, кэшем и бюджетами (S5).

### Оркестратор и исполнение

- Конечный автомат, DAG, checkpoints, retry, политики и approvals, журнал аудита. Прогон восстанавливается после падения worker'а без повторных коммитов (S2).
- Executors:
  - Local — allow-list команд; rlimits на POSIX, Job Objects на Windows (S9);
  - Docker-песочница — без сети и capabilities, только для чтения;
  - GitHub Actions (S4).
- **Egress-allowlist** (S9): шаги с сетью работают в изолированной сети, где единственный выход — прокси со списком хостов. Без DNS, без прямых маршрутов, с защитой от SSRF.
- **gVisor** (S9): `execution.docker.runtime: runsc`.

### GitHub

- PR под политикой и approval (без merge), check runs и комментарии без дублей, проверка правил ветки, reusable workflows, пилоты на двух стеках (S4).

### Self-Hosted сервер (S8, S9)

- REST API ТЗ §13 с `Idempotency-Key`.
- Пользователи и токены; RBAC на сервере; изоляция проектов — чужое неотличимо от несуществующего.
- Журнал аудита, включая попытки доступа к чужим проектам.
- Очередь в БД (PostgreSQL `SKIP LOCKED`), worker'ы на ≥ 10 прогонов, `serve --workers N`, общий rate limiter.
- Web UI на React, метрики Prometheus, хранилище артефактов S3/MinIO.
- docker-compose с Caddy (TLS), backup, ротация ключей, экспорт и retention.

### Качество и безопасность (S9)

- Приёмочная матрица AC-01…AC-10 в CI.
- Нагрузочный тест k6 (API + worker'ы на PostgreSQL).
- Проверка прав по всем маршрутам OpenAPI, fuzzing API (Schemathesis), конфигурации и redaction (Hypothesis), 26 проб выхода из песочницы.

### Исправлено в S9

- DoS через YAML-«billion laughs» в `.ai-coding.yml`.
- `security.network: local-only` пропускал внешний `base_url` у Ollama и vLLM.
- Токены `aic_…` не маскировались в логах.
- Ошибки фреймворка шли не в едином формате API.
- Разбор YAML и JSON Schema на каждый запрос к прогону.
- Инструмент, пишущий в копию дерева, терял установленные зависимости проекта.

### Исправлено после ревью кода (до выпуска)

- Проверка раскрытия YAML-алиасов зависала на узле, который содержит сам себя (`a: &x [*x]`). Теперь такой документ отклоняется.
- Симлинк `node_modules`/`vendor` в проверяемом репозитории монтировал в песочницу каталог хоста. Теперь зависимости копируются, а ссылки за пределы проекта отбрасываются.
- Зависимости, смонтированные только для чтения, ломали инструменты, которые пишут кэш (`node_modules/.vite`, `.cache`).
- Egress-прокси пропускал для HTTP чужой `Host` и второй запрос в keep-alive-соединении (domain fronting). Теперь он пересобирает ровно один запрос.
- `local-only`: адрес модели проверялся один раз, и DNS rebinding мог увести запросы наружу. Теперь проверяется каждый запрос, и подключение идёт к проверенному адресу.
- Windows: CPU-бюджет Job Object не учитывал число ядер. Процесс, который не удалось поместить в задание, оставался без лимитов.
- Общий rate limiter:
  - при недоступной БД задерживал запросы — теперь пауза между попытками;
  - при переполнении таблицы ключей терял неотправленные счётчики;
  - на SQLite при `serve --workers N` у каждого процесса был свой лимит.
