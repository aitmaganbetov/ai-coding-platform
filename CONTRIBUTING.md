# Contributing

1. Прочитайте [ТЗ](AI_Coding_Platform_v2_1_TZ.md), [архитектуру](docs/architecture/overview.md) и [правила разработки](docs/development.md).
2. Выберите задачу из [backlog](docs/backlog.md) текущего спринта. Следующий спринт не начинается, пока проверки текущего не завершены.
3. Создайте ветку от `main` (`feat/B-110-state-manager`), не коммитьте в `main` напрямую.
4. Код + тесты + документация в одном PR. `make check` (или эквивалентные `uv run …`) должен проходить локально.
5. Архитектурные изменения — с ADR.
6. Conventional Commits.
